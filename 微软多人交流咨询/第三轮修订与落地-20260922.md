## 一、分歧 #1 的裁决实现：`core/context-strategy.js`

第二轮裁决：**"Hy4 的注入公式 + KIMI 的触发条件"**。本轮把它写成可运行代码：

```
prompt = 角色前缀 + [早前摘要] + [最近 N 轮原文 N=2] + [本轮任务]
```

**触发条件（KIMI，不是固定 round%3）**：
- **条件 A**：累计注入 > 6000 字符 → 压缩（不是每轮都压，省 API 成本）
- **条件 B**：某 AI 连续 2 轮"跑偏" → **单点重置**（只清它一个，其它 8 个继续用各自的历史）

**关键设计：每个 AI 独立预算**（`budgets` Map），避免 9 个 AI 共用一个阈值互相挤占。

9 个用例锁死：
- 同一任务 + 不同角色 → 输出必然不同（**这是防"9 个复读机"的核心**）
- 注入公式四层全在场且顺序固定
- 超阈值才压缩 / 没超不压
- 跑偏 2 轮才重置，且**只重置该 AI 不影响其它**（KIMI 裁决的直接实现）

## 二、客户端 P0 改动（附件真实路径）—— 本轮最重要的地基

### 为什么要先做这个

第二轮 §七 钉死的根因链里，**根因 D 是"attachedFiles 无 localPath，阻塞 AttachmentBus"**。
不补它，附件握手门闩没有落点。这是 P1/P2/P3 的前置地基。

### 三处改动（全部小改，未碰客户端核心逻辑）

**① `desktop/src/main.js` —— 新增 `meeting:saveAttachment` IPC**

```
renderer (ArrayBuffer 字节) → 主进程
  ├─ ① 只写进 <tmp>/dsh-meeting-files/session_<key>/
  ├─ ② basename + 白名单字符过滤（拦 ../ 与绝对路径）
  ├─ ③ 单文件 200MB 上限 / 单会话 2GB 上限
  └─ 返回 { ok, localPath, size, mime, sha256 }
```

★ **安全校验三件套缺一不可**——否则 renderer 借主进程就能写任意位置（一个"任意文件写"漏洞）。
这直接实现了第二轮 §P0 提示里的"必须校验"。

**② `desktop/agent/meeting-preload.js` —— 暴露 `saveAttachment`**

`contextBridge` 不传 `Buffer`（会抛错），改传 `ArrayBuffer`（安全的结构化克隆类型）。主进程 `Buffer.from(bytes)` 接住。

**③ `desktop/agent/meeting.html` —— `handleFiles()` 补 `localPath`**

★ **所有格式**（txt/图片/PDF/其它）统一先落盘。文本类额外保留 `.text` 供"拼进 prompt"路径用；
非文本类现在终于有了 `localPath`——这是从"永远只发占位符"变成"可以真上传"的第一步。

### 配套（P3-lite + 盲点 A）

- `agentCatalog.js`：9 个 provider 各配 `charLimit`（按官方/实测保守值），
  并抽出 `INLINE_MAX=4000` / `DEFAULT_CHAR_LIMIT=10000` 具名常量，**杀掉两处魔法数字**。
- `meeting.html`：新增 `AGENT_ROLES`（盲点 A 的角色分化），每个 AI 发送时拼自己的角色前缀。
  > 注意：这份角色表**内联在 meeting.html**（渲染进程不能跨进程 require `context-strategy.js`）。
  > 注释已标明"Phase 2 接入 Meeting Core 时由 `context-strategy.js` 取代，届时删除内联段"。

### 验证

```
node --check src/main.js ✓
node --check src/agentCatalog.js ✓
node --check agent/meeting-preload.js ✓
meeting.html 内联 script 编译 ✓（29405 字节，语法无误）
```

⚠️ **未做运行时验证**：这些改动需要 `npm start` 起 DSH 桌面端、手动拖文件，
才能确认 `saveAttachment` 真的写盘成功。这是**真机验收项**，留待 §四。

## 三、盲点 C 的落地：`core/summarizer.js`

第二轮 §八·盲点 C："每轮结束产出轮纪要（≤300 字/轮）+ 每 5 轮做一次全局压缩"。
之前只有口号，没有可运行的东西。本轮落成 8 个用例：

- **轮纪要 ≤300 字**（没有压缩器时也用截断兜底，绝不限破）
- **每 5 轮才全局压缩一次**（不是每轮都压，省 API 成本）
- **压缩器失败优雅降级**（不炸、不阻塞会议——共识 #5 的"绝不锁死"精神）
