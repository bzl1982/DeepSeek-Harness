## 本轮最重要的发现：两个必然误判的真 bug

这两个 bug **光看文档永远看不出来**，写成可运行测试台后才暴露——这正好证明了"Phase 0 先做独立测试台"的判断是对的。

**Bug 1：`streamEnd` 是永久闩锁**
`web-adapter.js` 里 `let streamEnded = false` 挂在模块级，而 adapter 被 9 个 AI **复用整场会议**。第一轮结束后它永不复位 → 第二轮白送一个信号 → 配上 `minSignals: 2`，**第二个 AI 的回复在 0ms 内被判"已完成"**，抓到空串。

**Bug 2：`domStable` 起手即真 → 抓空气**
探针在"AI 还没开始生成"时，页面本来就静止，于是 `stopGone + sendReady + domStable` 三信号齐活 → 判定完成，而 `text` 是空串。**只在网络慢/首字节延迟高时偶发**——典型难查 bug。

两个都修了，并且做了**变异测试**：把修复退回去，测试立刻失败（不是假保险）。

## 兑现了文档承诺但不存在的东西

`streamEnd` 在上一轮被列为"信号 D"，但代码里**永远是 false**——一个恒定信号位在 `minSignals` 计数里等于让人，抗误判能力被悄悄削弱。

现在用 `core/stream-tracker.js` 真正接上了 CDP Network 域。核心设计是**不猜"哪个请求才是回答"，而是看"网络还有没有在流"**（活跃流计数 + 静默期）。好处是网站改 API 路径时只会退化为 `idle` 而非误判结束。额外收益：**它不依赖 DOM，所以 Shadow DOM / iframe 穿透问题对它完全不存在**——这直接回答了上一轮开放问题 #2 的一半。

## 我纠正了上一轮文档的 3 处误判

按你的"争议问题去源头核实"的铁律，我读了实际代码，有三处上一轮说错了：

1. **`charLimit` 死代码说法不成立** — 实际是 `model ? model.charLimit : 10000`，回落到 10000，分批分支能触发。真正的坑是 `charLimit` 在 `agentCatalog.js`（唯一配置源）里**根本没定义** → 9 个 AI 上限全硬编码成 10000。
2. **"9 个 webview 抢 DropEvent"不准确** — drop 是宿主 document 统一接的，只有一个 `handleFiles`，还配了双重穿透保险，不存在抢。
3. **"sleep(3000) 是根因"对，但不完整** — 更前置的问题是：**PDF/图片压根没真上传**。`handleFiles` 对 PDF 只存 `'[PDF文件: xxx]'` 一行字，发送时拼进 prompt。所以对 PDF 而言不是"偶尔收不到"，而是"永远收不到内容"。

关键结论：`attachedFiles` 从不保留真实路径（`{name, text, isImage, dataUrl}` 里没有 `localPath`），**这直接阻塞了 AttachmentBus 接入**。所以 Phase 2 必须**先补路径、再上握手**，顺序不能反。
