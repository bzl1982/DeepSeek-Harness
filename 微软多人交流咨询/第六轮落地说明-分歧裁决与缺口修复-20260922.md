## §2 一处关键分歧：评标切片该用 `OTHERS` 还是 `CANDIDATES`

这是本轮唯一的实质分歧，也是我必须裁决的地方。

### Agnes 的主张

> 「草案 A·评标切片写 `ALL` 是 bug。`ALL` 包含自己 → 评标人看到自己出的那份方案时会自我加分（锚定）。
> 正确切片是 `OTHERS`（抽掉自己）——恰好是'其它所有出标者的方案'。」

### 我的判断：**方向对，解法错**

"怕自我加分"这个直觉是对的，但"抽掉自己"会引入两个更严重的新问题：

**① `OTHERS` 让各方案被排次数不等 → Borda 均值不可横向比较。**

`tournament` 的出标阶段是 `seat: 'all'`（全员出标）→ 评标者本人**也是出标者**。
于是 `OTHERS` 下每个评审者只排 `N-1` 份，**且各人排除的不是同一份**：

```
9 人出标、3 人评标：
  方案 X 的作者是评标者 → X 被排 2 次
  方案 Y 的作者不是评标者 → Y 被排 3 次
→ 分母不同 → 均值不可比（结论会系统性偏向"被排次数多"的方案）
```

而 `bordaMeans` 用"被排次数"当分母，**不会崩、不会报错，只是悄悄给出失真的结论** —— 最难发现的一类故障。

**② `OTHERS` 在第 2 轮起会让评审者看到上轮别人的评分 → 跟票。**

`tournament` 是 `loop: true` 模式。第 2 轮时 `messages` 里已经有第 1 轮的评标名次表，
而 `OTHERS` **只过滤"自己的"**，别人的评分照放行 → 评审者会跟着上轮的名次排。
**"评标必须防跟票"是四家共识（GPT5/混元/豆包/谷歌都提到了）。**

**③ 匿名化本身就解决了"自我加分"，不需要靠"抽掉自己"。**

认不出哪份是自己写的 → 就不存在自我加分。而匿名同时带来两个额外好处：
候选集合与顺序对**所有评审者完全一致**（可聚合）+ 不含任何历史评分（防跟票）。

### 这正是四家共识项

> 共识第 9 项：**候选匿名化 + 随机顺序**

Agnes 是我问的 6 家里**唯一**主张 `OTHERS` 的。四家都要求匿名化。

### 落地：新增 `SLICE.CANDIDATES`

```js
CANDIDATES: 'candidates',   // 全部候选，匿名 + 定序 + 不含任何评分/名次
```

**定序用内容哈希（FNV-1a），不用 senderId**：

```js
.sort((a, b) => a.key - b.key || a.author.localeCompare(b.author))
```

为什么必须是内容哈希：
- 对所有评审者是**同一顺序** ✔
- 与"谁写的"**无关** ✔（换个人写同样的内容，仍是同一个标签 —— 否则等于没匿名：第一个出标的人猜得到自己是 A）
- **跨轮稳定** ✔（未被修改的候选，轮次间标签不变，便于"连续两轮同一定标"判据）

`tournament` 的评标阶段已从 `OTHERS` 改为 `CANDIDATES`，并在断言消息里写清三条理由（防下个会话改回去）。

## §3 我落地的三项缺口修复（Agnes 没触及的）

### P0-A：`chairman` 缺 `loop` → "每一轮追问"从未生效过

**这是真 bug，不是设计选择。**

`chairman.desc` 写着"主持人**在每一轮**根据分歧点动态点名追问"，`stopWhen: 'no-new-question'` ——
但模式定义里**没有 `loop` 字段**。而执行层是：

```js
const maxIter = mode.loop ? (mode.maxIterations || 5) : 1;
//              ↑ undefined → maxIter = 1 → 只跑一轮
```

**后果**：`no-new-question` 是**死代码** —— 第 1 轮 `shouldStop` 恒返回 `stop:false`，
随即被 `iteration >= maxIter` 打断，**判据根本没被用上**。宣传的核心卖点（每轮追问）从未发生过。

**修法（两步都必须做）**：`loop: true` + `maxIterations: 4`。
只加上限没用 —— `loop` 为假时 `maxIter` 恒为 1。

> ★ 顺带修正另一家的判断：混元说"`chairman` 缺 `maxIterations` 是成本黑洞"。
> **实测相反**：因 `loop` 缺失它只跑一轮、成本**最小**（不是黑洞）。
> "加 maxIterations"这药**对不上症**（加了也不会被读）。真修法是**先 `loop:true` 再设上限**。
> → 这就是"外部建议必须过一遍本地代码"的实例。

### P0-B：成本维度（四家里的四家列为最高优先级）

用户原话：**"在那里瞎聊浪费 TOKEN 就没意思了"**。
但改动前 `cost` / `budget` / `maxCalls` / `limits` / `tier` 在 `core/modes.js` 里 **grep 全空** ——
点"开始会议"之前完全看不到要花多少。

新增 `estimateCost(modeId, ctx)`，给**两个互补指标**：

| 指标 | 含义 | 为什么不能只看这一个 |
|---|---|---|
| `calls` | 调用次数 | 花在"次数"上的钱 |
| `contextInjections` | 上下文注入份数 | 花在"字"上的钱 —— **这才是 O(N²) 的体现** |

**关键洞察（实测发现，与 Agnes 和我们的直觉都不符）：**

```
panel 9 人：  会诊阶段  注入 36 份
              归并结论阶段 注入 117 份   ← 真正的大头（占 76%）
```

Agnes 说"分 3 组，注入 36→12（降 1/3）"—— **它只算了会诊那一段**。
按全阶段实测：**153 → 84，省 45%**，而省下来的主要来自归并阶段（117→63）。

所以我在建议里明确写下**分组收益的成立前提**：
> 归并阶段只读**组长摘要**（不读组内明细）—— 需编排层按 `groupLeaders` 标记限定可见消息，否则分组白做。

**已落地的三处**：
1. `estimateCost` / `costOverview`（core，可单测）+ 13 个测试
2. **测试台**：点"开始会议"前打印档位 / 单轮调用 / 最坏调用 / 注入份数 + 降本建议
3. **速查页**：每个模式卡带成本明细表（逐阶段"发言人数 × 注入份数"）+ 一张全模式成本对照表 + 降本顺序（①减人 ②分组 ③换轻档 ④别硬顶轮数）

### P0-C：Borda 接线（原"贯通性缺口"）

改动前：`bordaMeans` / `tournamentStop` **只有测试调用，生产代码零调用**；
`shouldStop` 被调用时**没传 `winnerId` / `prevWinnerId` / `buildPass`**
→ 智能判停永不生效，只能跑满 `maxIterations`。

**本质是"AI 自然语言 → 结构化数据"的解析层整个没写。** 本轮补齐三件：

**① 解析层 `parseBallots(reviews, { labels })`**

支持各模型的实际输出习惯（不是"要求 JSON 然后祈祷"）：
- JSON 对象 `{"方案A": 1, ...}` / JSON 数组 `[{"proposal":...,"rank":...}]`
- 序号前缀 `1. 方案A` / 标签后缀 `方案A 第 2 名` / `方案A：3`
- 表格行 `| 方案A | 1 |`（会把标签与数字切到相邻子句，单独处理）

带**防幻觉**（提到不存在的方案 → 忽略 + 告警）、**不猜**（解析失败 → 该票作废并计入 `failed`）、
**漏排告警**（`coverage` 不等 → 显式提示"不完整排序"）。

**② 输出契约 `produces`**

切片的**输入侧**做了（看什么），但**输出侧**没做 —— 消息没有类型标记，
于是 `CANDIDATES` 分不清"候选方案"和"评标意见"（后者含评分 → 若被当成候选发出去就**跟票**）。

修法：`mode.phases[].produces`（`candidate`/`ballot`/`verdict`/`revision`/`artifact`/…）
→ 编排层透传 → `message.kind` → `CANDIDATES` 按 `kind` 筛。

**③ 判据输入告警：把"静默失效"变成"显式告警"**

```js
if (winnerId == null) {
  return { stop: false, degraded: true, missingInput: ['winnerId'],
           reason: '★ 判据缺输入：未传入 winnerId → Borda 未接线，本判据无法生效，将跑满迭代上限' };
}
```

以前缺输入时判据会说"尚无定标结果"（**假装还没收敛**）——最难发现的故障。
现在会明说"我缺输入"，测试台会用红字显示。

> ★ 附带修了一个自己埋的坑：`buildPass` 的默认值原本是 `false`，
> 但 `false` 是**合法值**（"集成确实没通过"）→ 无法区分"没传"和"没通过" → 缺参检测永不触发。
> 改用 `null` 作哨兵。

**④ 定标不再让 AI 拍板**

新增 `buildVerdictPrompt({ candidates, borda })`：把**代码算出的 Borda 均值表**喂给定标席，
并明确告诉它"名次汇总由代码统计得出，不是谁的主观印象；你的任务是**确认结论并说明理由**，
若认为有误必须指出哪份名次表算错了，**而不是重新投票**"。

> 我在这里**自己犯过一次错并当场修掉**：初版把"匿名标签→真实作者"的映射也写进了 prompt
> （想的是"标注一下是审计用"）。那会**彻底破坏匿名性** —— 定标者会带着"这是谁写的"的品牌偏见。
> 已改为**绝不进 prompt**，并加了测试断言防回归。
