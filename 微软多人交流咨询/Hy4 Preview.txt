下面按“**先确认微软项目 → 拆解 AutoGen 原理 → 网页版接入的难点 → 可落地架构 → 代码示例 → 里程碑**”给你一套完整方案。  
我尽量写成可以直接排期开发的形式。

---

## 0. 先确认：微软这个项目大概率是 **Microsoft AutoGen**

你说“微软开源的多人 AI 对话交流项目”，基本可以确定是：

| 项目 | 是什么 | 和你的关系 |
|---|---|---|
| **Microsoft AutoGen** | 多智能体对话/群聊框架，核心是 `Agent / GroupChat / GroupChatManager` | **就是你要接入的核心** |
| **AutoGen Studio** | AutoGen 的低代码 Web 界面 | 可选，用来可视化配置 9 个 Agent |
| **Magentic-One** | 微软基于 AutoGen 做的多智能体系统：Orchestrator + WebSurfer + Coder + Terminal 等 | 偏“自动完成任务”，不是“9 个 AI 开会”的前端，不建议直接拿来当你的通辽会议 |
| **Semantic Kernel Agent Framework** | 微软另一个 Agent 编排框架，偏插件/企业集成 | 如果你以后要接 Office/企业系统可以再考虑 |

- AutoGen GitHub：`https://github.com/microsoft/autogen`
- 文档：`https://microsoft.github.io/autogen/`
- 你的理解是对的：**AutoGen 原生设计就是“多个 API 接口的 LLM/Agent 在一起群聊”**。官方例子里经常是 planner、engineer、critic、user 等多个 Agent，每个 Agent 背后是一个 OpenAI/Azure/本地模型接口。  
  所以“9 个 API 版的 AI 对话”是它的原生场景；而你的“9 个网页版 AI”需要加一层适配器。

## 1. AutoGen 的工作原理

### 1.1 核心抽象

AutoGen 的核心是：

```text
ConversableAgent（可对话代理）
  ├─ send / receive
  ├─ generate_reply：收到消息后如何生成回复
  └─ 注册多个 reply 函数：人、工具、代码执行、LLM……

AssistantAgent      = 会用 LLM 回复的 Agent
UserProxyAgent      = 代表你/用户，可发起聊天、请求人工输入、执行代码
GroupChat           = 群聊消息池
GroupChatManager    = 主持人/调度器，决定下一个谁说话
```

### 1.2 群聊流程

```text
你 / UserProxy
   │  发送议题：“请阅读附件并回答……”
   ▼
GroupChatManager
   │  选择下一个发言人
   │  speaker_selection_method:
   │    - round_robin：轮询，先让 9 个 AI 都答一遍
   │    - random
   │    - manual
   │    - auto：用一个“主席 LLM”来决定谁接着说
   ▼
Agent_i.generate_reply(messages)
   │
   ├─ 默认路径：走 LLM API
   │    messages → OpenAI/Azure/本地 /v1/chat/completions
   │
   └─ 可扩展路径：
        register_reply(自定义函数)
        或自定义 model_client
        → 你可以在这里改成“调用网页版 AI”
   │
   ▼
回复写回 GroupChat.messages
   │
   ▼
判断是否终止：
   - is_termination_msg：出现“会议结束”
   - max_round：最大轮次
   - 所有 Agent 都发过言
   │
   ▼
结束后由 Secretary / UserProxy 总结成会议纪要
```

### 1.3 AutoGen 为什么“原生适合 API”

因为 `Agent_i.generate_reply()` 默认会调用：

```python
generate_oai_reply()
```

它把 AutoGen 的 `messages` 转成 OpenAI 格式，发到：

```text
POST {base_url}/chat/completions
```

返回：

```json
{
  "choices": [
    {"message": {"role": "assistant", "content": "……"}}
  ]
}
```

所以只要你的网页 AI 能伪装成一个 **OpenAI 兼容接口**，AutoGen 几乎不用改。

## 2. 网页版 9 个 AI 和 API 版 AI 的本质差异

| 能力 | API 版 AI | 网页版 AI | 你怎么克服 |
|---|---|---|---|
| 调用方式 | HTTP `/chat/completions` | DOM 输入、点击发送、读聊天区 | 用 Playwright/扩展把它包成接口 |
| 返回 | 同步 JSON | 流式渲染、异步完成 | MutationObserver / 轮询 / 等“停止生成”消失 |
| 登录态 | API Key | Cookie / 浏览器 Session | `launch_persistent_context` 或浏览器扩展 |
| 文件 | base64 / multipart | 网页 `<input type=file>` / 上传组件 | 中央文件服务 + `set_input_files` |
| 上下文 | 你自己传 messages | 每个网页只记得自己页面里的历史 | 显式把会议记录喂进 prompt |
| 并发 | 天然并发 | 9 个页面可能互相阻塞 | async Playwright，每个 AI 一个 Page |
| 反爬/合规 | 正常调用 | 可能违反网站 ToS | 优先官方 API；网页版仅限内部研究/低频 |

关键点：**你现在的 “deepseek harness + 9 个网页同框 + 发文件/问题 9 个都能收到”，其实已经完成了最难的一层：网页自动化执行器。**  
AutoGen 不该重复造轮子，而是调用你这层。

---

## 3. 推荐总体架构：Web2API 网关 + AutoGen 编排

最稳的落地方式是：

```text
┌──────────────────────────────────────────────────────┐
│  通辽会议前端 / 你的 UI                                 │
│  展示：用户问题、9 个 AI 回答、主席调度、会议纪要           │
└───────────────┬──────────────────────────────────────┘
                │ WebSocket / HTTP
┌───────────────▼──────────────────────────────────────┐
│  AutoGen 编排后端                                      │
│  - UserProxy：你                                      │
│  - 9 个 AssistantAgent，每个代表一个网页 AI               │
│  - GroupChatManager / Selector：会议主持人               │
│  - Secretary：纪要生成（建议用 DeepSeek API 或本地模型）   │
└───────────────┬──────────────────────────────────────┘
                │ 调用“模型接口”
┌───────────────▼──────────────────────────────────────┐
│  Web2API 网关 / 你的 deepseek harness                  │
│  把 9 个网页 AI 暴露成 OpenAI 兼容模型：                 │
│  model = tongliao-01 ... tongliao-09                  │
│  POST /v1/chat/completions                            │
└───────────────┬──────────────────────────────────────┘
                │ Playwright / Electron / 浏览器扩展
┌───────────────▼──────────────────────────────────────┐
│  9 个网页版 AI                                         │
│  DeepSeek / Kimi / 豆包 / 元宝 / ChatGPT / Claude ...  │
└──────────────────────────────────────────────────────┘
```

### 这个架构的核心思想

> **让 AutoGen 以为它在调用 9 个普通 API 模型；实际上每个“模型”背后是你的一个网页 AI。**

## 4. 方案 A：最推荐先做 —— Web2API 网关

### 4.1 思路

你已经能控制 9 个网页 AI。现在加一个 HTTP 服务：

```text
POST http://127.0.0.1:8000/v1/chat/completions
{
  "model": "tongliao-01",
  "messages": [
    {"role": "system", "content": "你是参会专家A……"},
    {"role": "user", "content": "请阅读附件并回答……"}
  ]
}
```

你的服务收到后：

1. 把 `messages` 拼成网页 AI 能懂的 prompt；
2. 如果消息里带了文件，就上传文件到对应网页 AI；
3. 等待网页 AI 回复完成；
4. 返回 OpenAI 格式 JSON。

这样 AutoGen 侧完全不用改架构。

---

### 4.2 Web2API 服务示例：FastAPI

```python
# web2api.py
import json, time
import uvicorn
from fastapi import FastAPI, Request

# 这里复用你现有的 harness，每个 AI 一个控制器
# 例如：from your_harness import get_page
PAGES = {
    "tongliao-01": get_page("deepseek"),
    "tongliao-02": get_page("kimi"),
    "tongliao-03": get_page("doubao"),
    # ... 共 9 个
}

app = FastAPI()

def build_prompt(messages):
    """
    把 OpenAI 格式 messages 转成网页 AI 的 plain prompt
    """
    system = next((m["content"] for m in messages if m["role"] == "system"), "")
    rest = [
        f"{m['role']}: {m['content']}"
        for m in messages if m["role"] != "system"
    ]
    return "\n".join([system] + rest)

@app.post("/v1/chat/completions")
async def chat_completions(request: Request):
    body = await request.json()
    model = body.get("model", "tongliao-01")
    messages = body["messages"]

    prompt = build_prompt(messages)

    # 约定：用户消息里用 JSON 传文本和文件
    # {"text": "问题", "files": ["/tmp/a.pdf"]}
    files = None
    last_user = None
    for m in reversed(messages):
        if m["role"] == "user":
            last_user = m["content"]
            break
    if last_user:
        try:
            meta = json.loads(last_user)
            prompt = meta.get("text", prompt)
            files = meta.get("files")
        except Exception:
            pass

    page = PAGES[model]

    # 你现有 harness 的能力：把 prompt + files 发给这个网页 AI，等回复
    text = page.send_and_wait(prompt, files=files, timeout=300)

    return {
        "id": "chatcmpl-web",
        "object": "chat.completion",
        "created": int(time.time()),
        "model": model,
        "choices": [
            {
                "index": 0,
                "message": {"role": "assistant", "content": text},
                "finish_reason": "stop",
            }
        ],
        "usage": {"prompt_tokens": 0, "completion_tokens": 0, "total_tokens": 0},
    }

if __name__ == "__main__":
    uvicorn.run(app, host="127.0.0.1", port=8000)
```

### 4.3 AutoGen 侧接入

下面示例基于使用最广的 **AutoGen 0.2.x**（`pip install pyautogen==0.2.x`）。如果你用 0.4，思路一样，只是换成 `autogen-agentchat` 的 `AssistantAgent` 和 `SelectorGroupChat`。

```python
import json
from autogen import AssistantAgent, UserProxyAgent, GroupChat, GroupChatManager

def make_llm_config(model_name):
    return {
        "config_list": [
            {
                "model": model_name,
                "base_url": "http://127.0.0.1:8000/v1",
                "api_type": "openai",   # 伪装成 OpenAI 兼容接口
                "api_key": "sk-no-need",
                "price": [0, 0],        # 避免 AutoGen 计费警告
            }
        ],
        "temperature": 0.3,
        "timeout": 300,
        "stream": False,                # 先关掉流式，简化实现
        "cache_seed": None,             # 重要！关掉缓存，否则会命中旧答案
    }

agent1 = AssistantAgent(
    name="DeepSeek网页",
    system_message="你是参会专家1，擅长归纳和推理。请用中文回答。",
    llm_config=make_llm_config("tongliao-01"),
    human_input_mode="NEVER",
)

agent2 = AssistantAgent(
    name="Kimi网页",
    system_message="你是参会专家2，擅长长文总结和质疑。",
    llm_config=make_llm_config("tongliao-02"),
    human_input_mode="NEVER",
)

# ... 建 9 个 agent3...agent9

user_proxy = UserProxyAgent(
    name="你",
    human_input_mode="NEVER",
    code_execution_config=False,
    llm_config=False,
)

groupchat = GroupChat(
    agents=[user_proxy, agent1, agent2, agent3, agent4, agent5, agent6, agent7, agent8, agent9],
    messages=[],
    max_round=12,
    speaker_selection_method="round_robin",  # 第一阶段：先让 9 个都答一遍
)

# 如果你想后面做“互相辩论”，需要一个主席 LLM。
# 主席建议用真实 API，比如 DeepSeek 官方 API，不要浪费网页 AI 做调度。
chair_llm = {
    "config_list": [
        {
            "model": "deepseek-chat",
            "base_url": "https://api.deepseek.com/v1",
            "api_type": "openai",
            "api_key": "你的DEEPSEEK_API_KEY",
        }
    ],
    "temperature": 0.2,
    "timeout": 120,
}

manager = GroupChatManager(
    groupchat=groupchat,
    llm_config=chair_llm,
)

# 发起会议
user_proxy.initiate_chat(
    manager,
    message=json.dumps(
        {
            "text": "请阅读附件并回答：这份财报的核心风险是什么？",
            "files": ["/tmp/财报.pdf", "/tmp/说明.txt"],
        },
        ensure_ascii=False,
    ),
)
```

## 5. 方案 B：更底层 —— 自定义 WebAgent

如果你不想走 HTTP 网关，也可以直接在 AutoGen 里写一个 `WebAgent`。

适合场景：

- 你想精细控制某个网页的 DOM；
- 文件/上传逻辑很复杂；
- 不想多一层 HTTP 服务；
- 想复用同一个网页会话里的历史上下文。

### 5.1 WebAgent 示例

```python
from autogen import ConversableAgent, UserProxyAgent

class WebAgent(ConversableAgent):
    def __init__(self, name, system_message, adapter, **kwargs):
        super().__init__(
            name=name,
            system_message=system_message,
            llm_config=False,        # 不走内置 LLM
            human_input_mode="NEVER",
            **kwargs,
        )
        self.adapter = adapter

        # 注册自定义回复函数，优先级放在最前面
        self.register_reply(
            trigger=[ConversableAgent, UserProxyAgent],
            reply_func=self._web_reply,
            position=0,
        )

    def _web_reply(self, recipient, messages, sender, config):
        # messages 是 AutoGen 的消息历史
        history = "\n".join(
            f"{m.get('name', m['role'])}: {m['content']}"
            for m in messages[-6:]   # 防止过长，只带最近几轮
        )

        prompt = (
            f"{self.system_message}\n\n"
            f"[会议记录]\n{history}\n\n"
            f"请你基于以上内容继续发言："
        )

        text = self.adapter.send_and_wait(prompt, timeout=300)
        return True, text
```

### 5.2 Playwright Adapter 示意

```python
import time

class PlaywrightAdapter:
    def __init__(self, page, input_sel, send_sel, file_sel, wait_sel):
        self.page = page
        self.input_sel = input_sel
        self.send_sel = send_sel
        self.file_sel = file_sel
        self.wait_sel = wait_sel

    def send_and_wait(self, prompt, files=None, timeout=300):
        p = self.page

        if files:
            p.set_input_files(self.file_sel, files)

        p.fill(self.input_sel, prompt)
        p.click(self.send_sel)

        # 等回复稳定：连续 3 次读到同样内容，认为生成结束
        start = time.time()
        last = ""
        stable = 0
        while time.time() - start < timeout:
            text = p.inner_text(self.wait_sel).strip()
            if text and text == last:
                stable += 1
                if stable >= 3:
                    return text
            else:
                stable = 0
                last = text
            time.sleep(1)

        return last or "[超时未获取回复]"
```

这种方式下，AutoGen 的 `GroupChatManager` 完全不用变，只是 9 个 Agent 不是 `AssistantAgent`，而是你的 `WebAgent`。

## 6. 让 9 个网页 AI 真正“开会”的关键

你现在的“发文件/问题，9 个都收到”，本质上只是 **广播第一轮**。AutoGen 的价值在于后面几轮。

### 6.1 第一阶段：轮询广播

```python
speaker_selection_method="round_robin"
```

效果：

1. 你发议题 + 文件；
2. Manager 让 agent1 答；
3. 再让 agent2 答；
4. ……直到 9 个都答完；
5. AutoGen 收集到 9 份答案。

这就是你现在的通辽会议，但由 AutoGen 统一调度。

---

### 6.2 第二阶段：交叉讨论 / 辩论

改成：

```python
speaker_selection_method="auto"
```

并给 `GroupChatManager` 一个“主席模型”，例如 DeepSeek API。

主席会看整个会议记录，然后决定：

- 下一个让谁发言；
- 让他点评谁；
- 让他补充哪一点；
- 是否结束会议。

---

### 6.3 上下文注入：网页 AI 不知道别人说了什么

这是网页版最大坑：

> 9 个网页 AI 是 9 个独立页面，它们互相看不到消息。

所以你必须在 prompt 里手动喂会议记录。推荐模板：

```text
你是参会专家：{角色}

[会议记录]
主持人: 议题是xxx
DeepSeek网页: 我认为风险是……
Kimi网页: 我补充一点……
豆包网页: 我不同意前面观点……

[当前任务]
请你点评 Kimi 网页的观点，指出是否有漏洞，并给出你的结论。
```

实现上，在 `WebAgent._web_reply` 里根据 `messages` 动态拼这段 prompt。

如果会议很长，超出网页 AI 的上下文窗口，就先用主席模型把历史总结成摘要，再喂给网页 AI。

---

### 6.4 文件怎么处理

建议流程：

```text
用户在前端上传文件
   ↓
后端保存到临时目录，得到 /tmp/xxx.pdf
   ↓
AutoGen 用户消息里带 files=["/tmp/xxx.pdf"]
   ↓
Web2API 网关或 WebAgent 解析 files
   ↓
对每个网页 AI 调用 page.set_input_files("input[type=file]", files)
   ↓
网页 AI 读取文件并回答
```

注意：

- 不同网页支持的文件类型和大小不同，要加适配；
- 太大会失败，可先提取文本/压缩/OCR；
- 如果你现在已经能“发文件 9 个都收到”，那这层你已经有了，AutoGen 只要复用它。

## 7. 怎么和你现有的“通辽会议前端”结合

你现在的形态是：

> 一个页面里 9 个网页 AI 同框，你发问题/文件，9 个都能收到。

有二种接法。

### 7.1 本地 Playwright / Electron 控制 9 个页面

如果你现在是 Electron 或多 Page Playwright：

- 继续保留 9 宫格；
- 但把“发消息”的动作改成由 AutoGen 后端调用；
- 前端只负责展示 AutoGen 的聊天流。

前端展示内容可以是：

```text
你：议题 + 文件
DeepSeek网页：……
Kimi网页：……
主席：下面请豆包点评 Kimi 的观点
豆包网页：……
……
纪要：本次会议结论如下……
```

---

### 7.2 浏览器扩展桥

如果你想保留真实浏览器登录态，不想服务端跑 Playwright：

- 写一个 Chrome MV3 扩展；
- 后台脚本连接你的 AutoGen 后端 WebSocket；
- 内容脚本注入到 9 个 AI 的页面/iframe；
- 收到后端指令后，填入输入框、点发送、用 `MutationObserver` 抓回复；
- 再把回复通过 WebSocket 回传 AutoGen。

难点：

- 跨域 iframe 不能直接被父页面操作；
- 但 MV3 内容脚本可以用 `all_frames: true` + 每个域名 host 权限注入；
- 文件上传在扩展里比较麻烦，建议文件已经提前上传，或者走本地 Playwright。

## 8. 稳定性和合规注意事项

### 必做

1. **关闭 AutoGen 缓存**  
   `cache_seed=None`，否则同样 prompt 会返回旧答案，不会真正请求网页。

2. **每个 AI 一个独立 Page / Context**  
   不要共用一个页面顺序问 9 次，否则上下文串台。

3. **超时和重试**  
   单个网页卡住不能拖垮整个会议。失败时返回：

   ```text
   [该网页AI本次未响应]
   ```

4. **登录态持久化**  
   用：

   ```python
   playwright.chromium.launch_persistent_context(user_data_dir="./profile-deepseek", headless=False)
   ```

5. **主席/纪要尽量用 API**  
   网页 AI 只负责“发言”，调度和总结用 DeepSeek API / 本地模型，省时间、降反爬风险。

### 合规提醒

网页自动化可能违反目标 AI 网站的服务条款。建议：

- 内部研究、低频使用；
- 正式产品优先使用官方 API；
- DeepSeek、通义、Kimi、豆包等如果有 API，就走 API；
- 只有没有 API 的网页版才用 Playwright/扩展适配器。

## 9. 落地里程碑

### M1：打通 1 个网页 AI

- 选 1 个网页 AI；
- 写好 `send_and_wait`；
- 用 Web2API 暴露成本地模型；
- AutoGen 里建 1 个 Agent 对话成功。

### M2：9 个网页 AI 轮询广播

- 9 个 adapter；
- `round_robin`；
- 文件能分发；
- 前端能看到 9 份回答。

### M3：稳定性

- 超时；
- 重试；
