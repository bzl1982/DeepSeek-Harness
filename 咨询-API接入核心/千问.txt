Q3: 密钥本地存储
一句话结论：Electron safeStorage + JSON 文件。这是 Electron 官方推荐的标准做法，平衡了安全性与开发复杂度。
理由：safeStorage 在 Windows 上使用 DPAPI，macOS 使用 Keychain，Linux 使用 libsecret。比明文 YAML 安全，比 keytar 少一个原生依赖编译步骤。
什么时候不该用：如果应用需要跨机器同步配置（如通过 Git），加密后的 blob 无法迁移。此时应使用环境变量或提示用户每次启动输入密钥。

Q4: 50 个席位的并发与性能
一句话结论：全局信号量限制并发数（默认 10） + requestAnimationFrame (rAF) 批量渲染 DOM。50 路 HTTP 流可以同时存在（TCP 连接开销不大），但 DOM 更新必须节流。
4.1 并发控制设计
HTTP 层：使用 AbortController 管理生命周期。不需要复杂的信号量库，一个简单的计数器即可。
渲染层：每个席位维护一个 pendingUpdates 队列。requestAnimationFrame 每帧清空队列并一次性更新 innerHTML 或 TextNode。

5.2 Usage 累计统一方案
由于各协议 Usage 返回时机不同（OpenAI 在最后，Anthropic 可能在中间或最后），建议：
实时估算：前端根据 token 计数库（如 tiktoken 的 JS 移植版，或简单按字符数/4 估算）显示“预估用量”。
最终校准：当 onDone 触发且收到准确 usage 时，更新数据库中的 totalUsage。
反例：不要依赖 API 返回的 usage 来实时更新 UI 进度条，因为延迟太高。
