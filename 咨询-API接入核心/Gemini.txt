Q1 多协议支持：内置哪几个适配器与中转站处理

结论：内置 openai-chat、anthropic-messages、gemini-native 3 个适配器即可覆盖 99% 场景；OpenAI Responses 尚在预览期无需抢跑，所有中转站统一使用 openai-chat 兼容处理。

成本与反例：

成本：低维护负担。新增协议只需实现一套固定接口。

反例：在同一个 fetch 逻辑里写无数个 if (provider === 'anthropic') 拼接请求体，导致核心文件膨胀至数千行，牵一发而动全身。

TypeScript
interface ProtocolAdapter {
  // 方法签名
  chatStream(
    config: { baseURL: string; apiKey: string; model: string },
    payload: { messages: UnifiedMessage[]; params: UnifiedParams },
    hooks: { onDelta: (text: string, thinking: string) => void; onUsage: (usage: Usage) => void },
    signal: AbortSignal
  ): Promise<void>;
  
  listModels(config: { baseURL: string; apiKey: string }): Promise<ModelMeta[]>;
}

// 统一消息体与参数
type UnifiedMessage = { role: 'user' | 'assistant' | 'system', content: string | (TextPart | ImagePart)[] };
type UnifiedParams = { temperature?: number; maxTokens?: number; reasoningLevel?: 'off' | 'standard' | 'max' };

各协议差异清单：

OpenAI：系统提示词在 messages 数组首位 (role: 'system')；流式 usage 需传 stream_options: { include_usage: true } 并在 [DONE] 前最后一块解析。

Anthropic：系统提示词是顶层字段 system: string；流式事件分 message_start、content_block_delta、message_delta（含 usage）。

Gemini：角色名强制为 user 和 model；系统提示词在顶层 systemInstruction。

最小可运行代码（OpenAI 适配器内核）：

JavaScript
async function openaiChatStream(config, payload, hooks, signal) {
  const body = {
    model: config.model,
    messages: payload.messages,
    stream: true,
    stream_options: { include_usage: true },
    temperature: payload.params.temperature
  };

  const res = await fetch(`${config.baseURL}/chat/completions`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json', 'Authorization': `Bearer ${config.apiKey}` },
    body: JSON.stringify(body),
    signal
  });

  const reader = res.body.getReader();
  const decoder = new TextDecoder();
  let buffer = '';

  while (true) {
    const { done, value } = await reader.read();
    if (done) break;
    buffer += decoder.decode(value, { stream: true });
    const lines = buffer.split('\n');
    buffer = lines.pop(); // 保留不完整的最后一行

    for (const line of lines) {
      if (line.trim() === '' || line.trim() === 'data: [DONE]') continue;
      if (line.startsWith('data: ')) {
        const data = JSON.parse(line.slice(6));
        if (data.choices?.[0]?.delta) {
          hooks.onDelta(
            data.choices[0].delta.content || '', 
            data.choices[0].delta.reasoning_content || ''
          );
        }
        if (data.usage) hooks.onUsage(data.usage);
      }
    }
  }
}

const FALLBACK_MODELS = ['gpt-3.5-turbo', 'gpt-4o'];
const META_DICT = {
  'gpt-4o': { context: 128000, vision: true },
  'default': { context: 8192, vision: false }
};

async function fetchModels(baseURL, apiKey) {
  try {
    const ctl = new AbortController();
    setTimeout(() => ctl.abort(), 3000); // 3秒超时降级
    const res = await fetch(`${baseURL}/models`, {
      headers: { 'Authorization': `Bearer ${apiKey}` },
      signal: ctl.signal
    });
    if (!res.ok) throw new Error('API_ERROR');
    
    const data = await res.json();
    return data.data
      .filter(m => !m.id.includes('embedding'))
      .map(m => ({
        id: m.id,
        ...(META_DICT[m.id] || META_DICT['default'])
      }));
  } catch (err) {
    console.warn('拉取失败，使用降级列表', err);
    return FALLBACK_MODELS.map(id => ({ id, ...META_DICT[id] }));
  }
}

const { safeStorage } = require('electron');

function saveKey(key) {
  if (safeStorage.isEncryptionAvailable()) {
    const encrypted = safeStorage.encryptString(key);
    return { data: encrypted.toString('base64'), method: 'safestorage' };
  }
  // 降级混淆 (防君子不防小人，单机够用)
  return { data: Buffer.from(key).toString('base64'), method: 'base64' };
}

function loadKey(savedObj) {
  if (savedObj.method === 'safestorage' && safeStorage.isEncryptionAvailable()) {
    return safeStorage.decryptString(Buffer.from(savedObj.data, 'base64'));
  }
  if (savedObj.method === 'base64') {
    return Buffer.from(savedObj.data, 'base64').toString('utf-8');
  }
  return '';
}

Q4 50 个席位的并发与渲染性能

结论：无需全局 50 并发 HTTP 限制（Node.js 底层能扛住 50 个长连接），但必须实现基于 requestAnimationFrame 的 DOM 渲染节流风暴控制，否则 50 个流同时 innerHTML/textContent 会卡死 Renderer 进程。

成本与反例：

成本：内存占用增加几 MB（需维护 50 个文本缓冲区），高收益。

反例：每次收到 SSE data 事件直接调用 document.getElementById('seat-x').innerText += text。50 个流 × 每秒 10 个 chunk = 每秒 500 次 DOM 重绘，UI 线程完全锁死。

  isRafScheduled: boolean;

最小可运行代码（合帧渲染器）：

JavaScript
class ThrottleRenderer {
  constructor(domElement) {
    this.dom = domElement;
    this.buffer = '';
    this.scheduled = false;
  }

  append(text) {
    this.buffer += text;
    if (!this.scheduled) {
      this.scheduled = true;
      requestAnimationFrame(() => this.flush());
    }
  }

  flush() {
    // 使用 textContent 而非 innerHTML 防 XSS 且性能更好，需要 Markdown 解析时再批量转
    this.dom.textContent += this.buffer; 
    this.buffer = '';
    this.scheduled = false;
  }
}
// 50 个席位各自实例化一个 ThrottleRenderer，互不干扰且由浏览器统一合帧

尝试 GET /v1/models (超时 3s)。

过滤掉 id 包含 embedding、tts、dall-e 的非对话模型。

如果抛错或返回空，读取 ~/.dsh/models_cache.json。

元数据附加：根据模型名正则匹配（如 /claude-3-5/ -> 200k，/gemini-1.5-pro/ -> 2M），找不到则给默认值（8k，不支持视觉）。元数据推荐直接抓取 LiteLLM 的 model_prices_and_context_window.json 作为本地基准。

最小可运行代码（拉取与合并元数据）：

JavaScript
const FALLBACK_MODELS = ['gpt-3.5-turbo', 'gpt-4o'];
const META_DICT = {
  'gpt-4o': { context: 128000, vision: true },
  'default': { context: 8192, vision: false }
};

async function fetchModels(baseURL, apiKey) {
  try {
    const ctl = new AbortController();
    setTimeout(() => ctl.abort(), 3000); // 3秒超时降级
    const res = await fetch(`${baseURL}/models`, {
      headers: { 'Authorization': `Bearer ${apiKey}` },
      signal: ctl.signal
    });
    if (!res.ok) throw new Error('API_ERROR');
    
    const data = await res.json();
    return data.data
      .filter(m => !m.id.includes('embedding'))
      .map(m => ({
        id: m.id,
        ...(META_DICT[m.id] || META_DICT['default'])
      }));
  } catch (err) {
    console.warn('拉取失败，使用降级列表', err);
    return FALLBACK_MODELS.map(id => ({ id, ...META_DICT[id] }));
  }
}

Q3 密钥本地存储

结论：推荐使用 Electron safeStorage 结合本地 JSON；不支持环境（如 Linux 缺少密钥环或 Windows DPAPI 损坏）静默降级为明文 Base64 混淆存储。

  baseURL: string; // 'https://api.openai.com/v1'

最小可运行代码：

JavaScript
const { safeStorage } = require('electron');

function saveKey(key) {
  if (safeStorage.isEncryptionAvailable()) {
    const encrypted = safeStorage.encryptString(key);
    return { data: encrypted.toString('base64'), method: 'safestorage' };
  }
  // 降级混淆 (防君子不防小人，单机够用)
  return { data: Buffer.from(key).toString('base64'), method: 'base64' };
}

function loadKey(savedObj) {
  if (savedObj.method === 'safestorage' && safeStorage.isEncryptionAvailable()) {
    return safeStorage.decryptString(Buffer.from(savedObj.data, 'base64'));
  }
  if (savedObj.method === 'base64') {
    return Buffer.from(savedObj.data, 'base64').toString('utf-8');
  }
  return '';
}

Q4 50 个席位的并发与渲染性能

结论：无需全局 50 并发 HTTP 限制（Node.js 底层能扛住 50 个长连接），但必须实现基于 requestAnimationFrame 的 DOM 渲染节流风暴控制，否则 50 个流同时 innerHTML/textContent 会卡死 Renderer 进程。

成本与反例：

成本：内存占用增加几 MB（需维护 50 个文本缓冲区），高收益。

反例：每次收到 SSE data 事件直接调用 document.getElementById('seat-x').innerText += text。50 个流 × 每秒 10 个 chunk = 每秒 500 次 DOM 重绘，UI 线程完全锁死。

渲染节流字段级设计：

TypeScript
class SeatRenderer {
  seatId: string;
  pendingText: string;
  pendingReasoning: string;
  isRafScheduled: boolean;
  domNodes: { content: HTMLElement, reasoning: HTMLElement };
}

最小可运行代码（合帧渲染器）：

JavaScript
class ThrottleRenderer {
  constructor(domElement) {
    this.dom = domElement;
    this.buffer = '';
    this.scheduled = false;
  }

  append(text) {
    this.buffer += text;
    if (!this.scheduled) {
      this.scheduled = true;
      requestAnimationFrame(() => this.flush());
    }
  }

  flush() {
    // 使用 textContent 而非 innerHTML 防 XSS 且性能更好，需要 Markdown 解析时再批量转
    this.dom.textContent += this.buffer; 
    this.buffer = '';
    this.scheduled = false;
  }
}
// 50 个席位各自实例化一个 ThrottleRenderer，互不干扰且由浏览器统一合帧

Q9 附件注入的协议差异

结论：前端统一将附件抽象为 { type, mime, name, dataBase64 }；核心协议层拦截 PDF 等复杂文件，使用本地库（如 pdf.js）提取纯文本后，再以普通字符串形式塞入 prompt 规避不同厂商的 PDF 支持差异。
