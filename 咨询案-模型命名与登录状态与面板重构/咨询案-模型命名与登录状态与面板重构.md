## 一、项目背景与运行环境（简述）

DeepSeek Harness 是 Electron 33.2.0 桌面客户端（Windows 11，4K）。它把 **9 个网页版 AI**（DeepSeek / ChatGPT / Kimi / 豆包 / 通义 / 元宝 / Gemini / 谷歌搜索 / 文心）封装成桌面应用，同时保留 dsh 自身的 API 模型能力。

三个相关界面：

1. **主窗口**：dsh Web UI（React SPA，`http://127.0.0.1:38123`，带 token 鉴权，外部无法直接读取 DOM，只能靠 `executeJavaScript` 注入脚本操作）
2. **通辽会议窗口**：独立 BrowserWindow 加载 `meeting.html`，3×3 宫格内嵌 9 个 `<webview>`（每个独立 partition `persist:agent-xxx`，各自保持登录态）
3. **设置 → 模型面板** 与 **主页输入框右下角的模型切换器**：都在 dsh SPA 内部，只能注入脚本修改

**关键约束**：
- 主窗口与会议窗口均 `sandbox: true`，preload 仅 contextBridge + ipcRenderer
- `<webview>` 是独立渲染进程（guest），鼠标/键盘事件与 DOM 读取都受限
- 9 个网站各有自己的登录态，存放在各自的 webview partition 里

### 诉求 2：主窗口「设置 → 模型」面板——网页版放 API 下面，显示登录状态和登录名

**用户原话**：
> 「设置-模型 网页版智能体放API的下面，API在上，网页版在下」
> 「网页版要显示是否登陆状态，还有登录名是什么」

**解读**：
- 「设置 → 模型」面板里，**API 模型排在上面，网页版智能体排在下面**（网页版不能占 API 的位置）
- 每个网页版智能体条目要显示：**① 是否已登录**（如 已登录 ✓ / 未登录 ✗）；**② 登录的账号名是什么**（如显示登录邮箱/用户名/头像 alt）

**现状**：
- main.js 有 `MODEL_SORT_JS`：每 3 秒把列表里匹配 `web/网页/deepseek-web/chatgpt-web/...` 的条目移到列表末尾（即网页版在下的思路已注入），但用户反馈似乎仍不对（可能该面板与模型切换器是两套列表，或排序选择器没命中）
- 登录状态目前只在**通辽会议窗口**里有检测（见诉求 4），主窗口设置面板**没有**任何登录状态/登录名显示

### 诉求 3：主页输入框右下角的模型切换器——命名统一 + 网页版仅登录才显示

**用户原话**：
> 「主页输入窗口右下角模型切换的地方，里面的智能体名字命名跟通辽会议大窗口里的命名一致，要统一」
> 「API的模型选中现在只能看见一个，被压缩了，弹出的页面不够大，只能显示一行API的模型，下面全部都是网页版写死的模型占了位置」
> 「这个地方的模型要设置页面里登录方可在这里显示，没登录不显示」

**解读**：
- 主页输入框右下角是**模型切换器**（下拉/弹出面板）
- 其中智能体的命名必须与通辽会议窗口命名**完全一致**（同一套「公司-产品」中文名）
- **当前问题**：面板太小 / 列表布局问题，API 模型被压缩到只能看见一行；网页版模型是**写死占位**（不管是否登录都固定占着列表下方的位置）
- **要求**：① API 模型正常完整显示；② 网页版智能体条目**只有在该网站已登录时才显示，未登录的隐藏**（或置灰？——待确认，用户说"没登录不显示"）

### 诉求 4（隐含前提）：网页版 AI 的登录状态与登录名检测

用户要求在设置面板和模型切换器里显示"是否登录 + 登录名"，这依赖**对 9 个不同网站的登录态检测**：

- 现状（会议窗口内）：每 8 秒用 `executeJavaScript` 在 webview 里检测——「存在"登录/登 录/Sign in/Log in/Login/立即登录"按钮 → 未登录；存在头像/用户菜单/profile/avatar 元素 → 已登录」，名牌上显示 绿点 ●（已登录）/ 灰点 ○（未登录）
- **局限**：只判断了"是否登录"，**没有提取登录名**（用户名/邮箱/头像 alt）；且不同网站（chat.deepseek.com / chatgpt.com / kimi.moonshot.cn / doubao.com / tongyi.aliyun.com / yuanbao.tencent.com / gemini.google.com / google.com / yiyan.baidu.com）的用户信息元素千差万别，没有统一选择器
- 主窗口要显示登录名，需要把检测结果**从会议窗口/各 webview 传到主窗口 dsh UI**（涉及 IPC + 注入），或另起一套检测机制
