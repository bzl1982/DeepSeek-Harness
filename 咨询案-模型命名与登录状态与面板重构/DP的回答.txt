下面按你的咨询案逐条给方案。核心原则先给三句：

1. **命名单一数据源**：只维护一份 `agentCatalog`，会议窗口、设置面板、模型切换器都从它取名字。  
2. **登录状态主进程集中管理**：webview 只负责检测并上报，主进程保存 `authState`，再广播给会议窗口和主窗口 dsh UI。  
3. **模型列表优先改数据源，其次改 CSS/显隐，最后才动 DOM 顺序**。每 3 秒 appendChild 移动节点会和 React 重渲染打架，是当前“排序不对/闪跳/被压缩”的高概率根因。

## A. 命名统一（诉求 1）

### A1. 建议最终命名表

你的要求是“每一个窗口左上角都改成中文”，但你自己也举例「月之暗面-Kimi」可接受。所以建议规则是：

> **公司名用中文；产品有官方中文名就用中文；没有官方中文名的品牌保留官方英文，不强行音译/意译。**

最终建议：

| id | 最终名称 |
|---|---|
| deepseek-web | 深度求索-DeepSeek |
| chatgpt-web | OpenAI-ChatGPT |
| kimi-web | 月之暗面-Kimi |
| doubao-web | 字节跳动-豆包 |
| tongyi-web | 阿里巴巴-通义千问 |
| yuanbao-web | 腾讯-元宝 |
| gemini-web | 谷歌-Gemini |
| google-search | 谷歌-搜索 |
| wenxin-web | 百度-文心 |

其中：
- 「谷歌搜索」→「**谷歌-搜索**」，已按你要求。
- 「阿里巴巴-通义」→「**阿里巴巴-通义千问**」，已按你要求。
- DeepSeek、ChatGPT、Kimi、Gemini 不建议强行改成“深度求索-深度求索”“聊天GPT”“双子座”，会非常生硬，而且和用户日常认知不一致。
- 如果用户坚持“一个字英文都不能有”，备选是：深度求索-深度求索 / OpenAI-聊天GPT / 月之暗面-Kimi / 谷歌-双子座。但我不推荐。

### A2. 单一数据源怎么做

建一个主进程可读的 `shared/agentCatalog.js`：

```js
// shared/agentCatalog.js
const AGENT_CATALOG = [
  {
    id: 'deepseek-web',
    name: '深度求索-DeepSeek',
    shortName: 'DeepSeek',
    type: 'web',
    url: 'https://chat.deepseek.com/',
    partition: 'persist:agent-deepseek-web',
    authProbe: 'deepseek'
  },
  {
    id: 'chatgpt-web',
    name: 'OpenAI-ChatGPT',
    shortName: 'ChatGPT',
    type: 'web',
    url: 'https://chatgpt.com/',
    partition: 'persist:agent-chatgpt-web',
    authProbe: 'chatgpt'
  },
  // ... 其余 7 个
];

module.exports = { AGENT_CATALOG };
```

主进程通过 IPC 暴露：

```js
ipcMain.handle('catalog:get', () => AGENT_CATALOG);
```

会议窗口 preload：

```js
contextBridge.exposeInMainWorld('dshCatalog', {
  get: () => ipcRenderer.invoke('catalog:get')
});
```

主窗口注入脚本时，先从主进程拿 catalog，再注入到 dsh 页面：

```js
const catalog = await mainWindow.webContents.executeJavaScript('window.dshCatalog.get()');
await mainWindow.webContents.executeJavaScript(`
  window.__DSH_CATALOG__ = ${JSON.stringify(catalog)};
`);
```

这样会议窗口名牌、设置面板、模型切换器都读同一份 `name`，不会再出现两处不一致。

## B. 登录状态 + 登录名检测（诉求 2、4）

### B1. “是否登录”不要只靠找登录按钮/头像

现有方案太通用，容易误判。建议改成：

> **Cookie 辅助 + 站点定制 DOM 探针 + 多候选回退 + 置信度。**

主进程可以先用 partition 的 Cookie 辅助判断：

```js
async function cookieProbe(partition, url, cookieNames) {
  const ses = session.fromPartition(partition);
  const cookies = await ses.cookies.get({ url });
  return cookieNames.some(name => cookies.some(c => c.name === name && c.value));
}
```

各站点关键 Cookie 参考：

| 站点 | 可辅助的 Cookie |
|---|---|
| DeepSeek | token / userToken |
| ChatGPT | `__Secure-next-auth.session-token` |
| Kimi | access_token |
| 豆包 | 登录相关 session |
| 通义 | 阿里登录票据 |
| 元宝 | 腾讯登录票据 |
| Gemini / Google | SID / SAPISID |
| 文心 | BDUSS |

Cookie 只能辅助“大概率已登录”，不能拿登录名。登录名还是从 DOM 取。

### B2. 登录名提取：逐站定制选择器配置表最稳

不要幻想一个统一选择器能覆盖 9 个站。建议：

```js
const AUTH_PROBES = {
  deepseek: {
    loggedOutText: ['登录', '登 录', 'Log in', 'Sign in'],
    userSelectors: [
      '[class*="avatar"] img',
      '[class*="user-name"]',
      '[class*="nickname"]',
      '[class*="userInfo"]'
    ],
    nameAttrs: ['alt', 'title', 'aria-label']
  },
  chatgpt: {
    loggedOutText: ['Log in', 'Sign up'],
    userSelectors: [
      '[data-testid="profile-button"]',
      'button[aria-label*="Account"]',
      'button[aria-label*="账号"]'
    ],
    nameAttrs: ['aria-label', 'title', 'alt']
  },
  // ... 其余站点
};
```

检测脚本在 webview 内执行：

```js
function probeAuth(cfg) {
  const visible = el => !!(el && el.offsetParent !== null && el.getBoundingClientRect().width > 0);
  const text = el => (el?.textContent || '').trim();

  // 1. 找登录按钮
  for (const el of document.querySelectorAll('button, a, [role="button"]')) {
    if (!visible(el)) continue;
    const t = text(el);
    if (cfg.loggedOutText.some(x => t === x || t.includes(x))) {
      return { status: 'loggedOut' };
    }
  }

  // 2. 找用户名/头像 alt
  for (const sel of cfg.userSelectors) {
    for (const el of document.querySelectorAll(sel)) {
      if (!visible(el)) continue;
      for (const attr of cfg.nameAttrs) {
        const v = el.getAttribute?.(attr) || el[attr];
        if (v && v.trim() && !/avatar|头像|profile|用户菜单/i.test(v)) {
          return { status: 'loggedIn', name: v.trim() };
        }
      }
      const t = text(el);
      if (t && t.length <= 30 && !/登录|注册|设置|菜单/.test(t)) {
        return { status: 'loggedIn', name: t };
      }
    }
  }

  // 3. 找头像但拿不到名字
  for (const sel of ['[class*="avatar"]', '[class*="user-menu"]', '[class*="profile"]']) {
    if ([...document.querySelectorAll(sel)].some(visible)) {
      return { status: 'loggedIn', name: '' };
    }
  }

  return { status: 'unknown' };
}
```

各站点已知特征，建议你实测后填入配置：

- ChatGPT：`[data-testid="profile-button"]`，`aria-label` 常含账号名。
- Google/Gemini：`[aria-label*="Google 账号"]`，头像 `img[alt]`。
- 文心：百度账号头像、昵称。
- Kimi：头像 + 昵称。
- 豆包/通义/元宝：头像 + 昵称/手机号。
- DeepSeek：很多情况下只显示头像，不显示昵称。拿不到就显示“已登录（账号隐藏）”。

**不要尝试从 JWT/Cookie 里解用户名**，不稳定且涉及安全边界。

### B3. 跨进程传递：主进程做唯一状态中心

链路建议：

```text
webview guest 检测
  → preload / executeJavaScript
  → 会议窗口宿主 meeting.html
  → ipcRenderer.send('auth:report')
  → 主进程 authState
  → 广播 auth:changed
  → 会议窗口名牌更新
  → 主窗口 dsh 注入脚本更新设置面板/模型切换器
```

主进程：

```js
const authState = new Map();

ipcMain.on('auth:report', (e, payload) => {
  const { id, status, name, avatar } = payload;
  const prev = authState.get(id);
  if (prev?.status === status && prev?.name === name) return;

  authState.set(id, {
    status,
    name: name || '',
    avatar: avatar || '',
    updatedAt: Date.now()
  });

  const snapshot = Object.fromEntries(authState);
  meetingWindow?.webContents.send('auth:changed', snapshot);
  mainWindow?.webContents.send('auth:changed', snapshot);
});

ipcMain.handle('auth:getState', () => Object.fromEntries(authState));
```

主窗口 preload：

```js
ipcRenderer.on('auth:changed', (e, state) => {
  window.postMessage({ type: 'DSH_AUTH_CHANGED', state }, '*');
});
```

主窗口注入脚本监听：

```js
window.addEventListener('message', ev => {
  if (ev.data?.type === 'DSH_AUTH_CHANGED') {
    window.__DSH_AUTH__ = ev.data.state;
    applyModelUI();
  }
});
```

### B4. 刷新与缓存

- 会议窗口 webview 打开时：`did-finish-load` 后立即检测一次。
- 轮询：15~30 秒一次，不要 3 秒。
- 导航事件：`did-navigate`、`did-finish-load`、`page-title-updated` 后立即检测。
- 缓存：`Map<agentId, {status,name,updatedAt}>`，TTL 30 秒。
- 只有状态或登录名变化才广播，避免 UI 频繁重绘。
- 登录名变化：换账号通常伴随导航/刷新，检测到 `name` 变化再广播。

## C. 模型切换器与设置面板布局（诉求 2、3）

### C1. 先定位：网页版条目到底从哪来

这是关键。你需要先确认模型切换器里的网页版条目是：

1. dsh 前端写死占位；
2. 来自 agent runtime 的 provider 列表；
3. 来自某个 API 返回。

建议先注入探针脚本，点击模型切换器后输出 DOM 和 React props：

```js
(() => {
  const out = [];
  document.querySelectorAll('button,[role="button"]').forEach(el => {
    const t = (el.textContent || '') + (el.getAttribute('aria-label') || '');
    if (/模型|model|切换|智能体/.test(t)) {
      out.push({
        tag: el.tagName,
        cls: el.className,
        text: el.textContent.trim(),
        aria: el.getAttribute('aria-label')
      });
    }
  });
  return out;
})()
```

点击后再查：

```js
document.querySelectorAll('[role="listbox"],[role="menu"],[class*="popover"],[class*="dropdown"],[class*="model"]')
```

把结构和 React props 键打印出来。只有确认来源，才能决定是“数据源过滤”还是“DOM 显隐”。

### C2. 根因判断

“API 模型只能看见一行，网页版写死占位占位置”通常是：

- 弹出面板容器 `max-height` 固定太小；
- API 分组没有独立滚动区；
- 网页版条目被当成普通模型插入，且数量多；
- 你的 `MODEL_SORT_JS` 每 3 秒 appendChild，触发 React 重渲染，导致列表被重置/压缩/闪跳。

### C3. 推荐改造顺序

1. **优先数据源过滤**：如果网页版来自 agent runtime，扩展 `listProviderMeta()` 返回 `auth.loggedIn`，前端自然只显示已登录。
2. **其次 CSS 分组**：给 API 组和网页版组分别设置容器：
   ```css
   .model-popover {
     max-height: min(70vh, 560px) !important;
     overflow: auto !important;
   }
   .model-group-api {
     flex: 0 0 auto;
   }
   .model-group-web {
     flex: 1 1 auto;
     overflow: auto;
   }
   .web-model[data-logged-in="false"] {
     display: none !important;
   }
   ```
3. **最后 DOM 显隐**：不要删除节点，只改 `style.display` / `hidden` / `data-logged-in`。
4. **排序用 CSS order 或数据源顺序**，不要每 3 秒 `appendChild`。

注入脚本示例：

```js
function applyModelUI() {
  const catalog = window.__DSH_CATALOG__ || [];
  const auth = window.__DSH_AUTH__ || {};

  document.querySelectorAll('[data-dsh-model-item]').forEach(el => {
    const id = el.getAttribute('data-agent-id');
    const item = catalog.find(x => x.id === id);
    if (!item) return;

    const label = el.querySelector('[class*="name"], [class*="label"]') || el;
    label.textContent = item.name;

    if (item.type === 'web') {
      const loggedIn = auth[id]?.status === 'loggedIn';
      el.style.display = loggedIn ? '' : 'none';
      el.setAttribute('data-logged-in', String(loggedIn));
    }
  });
}

const mo = new MutationObserver(() => requestAnimationFrame(applyModelUI));
mo.observe(document.body, { childList: true, subtree: true });
applyModelUI();
```

### C4. 设置面板和模型切换器统一管理

建议把“显示规则”抽成一份：

```js
const UI_RULES = {
  apiFirst: true,
  webOnlyLoggedIn: true,
  showAuthName: true
};
```

两个界面都读同一份 `catalog + authState + UI_RULES`。设置面板显示“已登录 · 张三”，模型切换器显示“已登录”或直接只显示已登录项。

## D. 一次性落地建议

推荐顺序：

1. **建 `agentCatalog` 单一数据源**，统一 9 个名称、URL、partition、authProbe。
2. **主进程 `authState` + IPC**：`auth:report`、`auth:getState`、`auth:changed`。
3. **会议窗口改造**：名牌读 catalog；登录检测上报；名牌显示名称 + 状态 + 登录名。
4. **主窗口注入改造**：先探针定位模型切换器/设置面板；再注入 catalog + authState；分组、排序、过滤、显示登录状态。
5. **拖拽文件修复**（见下）。
6. **打包实测**：杀进程 → `electron-builder --win --dir` → 启动 → 逐个登录/退出验证。

容易踩的坑：

- React 重渲染会重置 DOM，不要直接 appendChild 移动节点。
- `executeJavaScript` 要等 `did-finish-load`，并 catch 异常。
- webview 的 `executeJavaScript` 在 sandbox 下可用，但要注意 guest 页面 CSP。
- 登录检测选择器会随网站改版失效，必须配置化 + 多候选。
- 4K 缩放下 `offsetParent` 和坐标可能不准，用 `getBoundingClientRect`。
- dsh 前端更新后注入选择器可能失效，探针脚本要保留。

## 追加问题：通辽会议窗口拖拽文件收不到

这个问题的根因通常是：

> 会议窗口是宿主 `meeting.html`，里面是 `<webview>`。文件拖到窗口上时，事件被 webview 这个独立 guest 进程吃掉，宿主 `meeting.html` 收不到 `drop`。

### 推荐方案：给每个 webview 注入统一 DnD preload

主进程在会议窗口上监听 `will-attach-webview`：

```js
meetingWindow.webContents.on('will-attach-webview', (event, webPreferences, params) => {
  webPreferences.preload = path.join(__dirname, 'webview-dnd-preload.js');
});
```

`webview-dnd-preload.js`：

```js
const { ipcRenderer, webUtils } = require('electron');

window.addEventListener('dragover', e => {
  e.preventDefault();
  e.stopPropagation();
}, true);

window.addEventListener('drop', e => {
  e.preventDefault();
  e.stopPropagation();

  const files = [...(e.dataTransfer?.files || [])];
  const paths = files.map(f => {
    try {
      return webUtils.getPathForFile(f);
    } catch {
      return f.path;
    }
  }).filter(Boolean);

  ipcRenderer.sendToHost('dsh-file-drop', {
    paths,
    x: e.clientX,
    y: e.clientY
  });
}, true);
```

宿主 `meeting.html` 监听：

```js
document.querySelectorAll('webview').forEach(wv => {
  wv.addEventListener('ipc-message', ev => {
    if (ev.channel === 'dsh-file-drop') {
      const { paths, x, y } = ev.args[0];
      console.log('会议窗口收到文件', paths);

      // 如果你要转发给主进程
      window.dshAPI?.dropFiles?.({
        agentId: wv.dataset.agentId,
        paths
      });
    }
  });
});
```

注意：Electron 32+ 已移除 `File.path`，必须用 `webUtils.getPathForFile(file)`。如果在 sandbox preload 里 `webUtils` 不可用，需要测试；若不可用，可以临时把 webview 的 sandbox 关闭做验证，但正式版尽量保留 sandbox。

### 如果你想把文件“注入”到某个 AI 网站的上传框

宿主收到路径后，交给主进程，用 `webContents.debugger` 的 `DOM.setFileInputFiles`：

```js
ipcMain.handle('agent:attachFiles', async (e, { agentId, paths }) => {
  const wc = getWebviewWebContents(agentId); // 你需要保存 webview 的 webContentsId
  if (!wc) return { ok: false, reason: 'no webContents' };

  const dbg = wc.debugger;
  if (!dbg.isAttached()) dbg.attach('1.3');

  const { root } = await dbg.sendCommand('DOM.getDocument');
  const { nodeId } = await dbg.sendCommand('DOM.querySelector', {
    nodeId: root.nodeId,
    selector: 'input[type=file]'
  });

  if (!nodeId) return { ok: false, reason: 'no file input' };

  await dbg.sendCommand('DOM.setFileInputFiles', {
    files: paths,
    nodeId
  });

  return { ok: true };
});
```

如果上传框是点击后才出现，先 `executeJavaScript` 点击上传按钮，再查 `input[type=file]`。

### 需要你确认一点

拖拽文件的目标是：

1. 只要会议窗口/宿主收到文件路径即可？
2. 还是要拖到某个 AI 格子里，让那个 AI 网站收到文件并上传？

如果是要让 AI 网站收到，按上面 `DOM.setFileInputFiles` 做；如果只是宿主收到，preload + `ipc-message` 就够了。
