## §6 我的初步草案（请当靶子批判，方向错了请直接推翻）

**草案：把 `cdp-set-files` 重构成「每站点 adapter + 统一验收」**

1. 每站点配置升级为 adapter 对象：
```
{
  id,
  prepare: optional fn(webview) -> 进到可承接文件的界面（如谷歌点 AI 模式）,
  open:    optional fn -> 点页面 📎 打开 chooser（返回 chooser 已开的 Promise）,
  drop:    optional bool -> 启用合成拖放,
  direct:  optional bool -> 启用直塞 input,
  isAttached: (before, after, fileName) -> 'staged'|'consumed'|'no-chip'   // 统一验收
}
```
2. 统一验收 `isAttached`：**发前快照 `before` = 各 input.files 名集合 + body 含 fileName 否；发后 `after` 同样**。`staged` = after 含 fileName 且 before 不含；`consumed` = before 含/after 不含 + 正文出现芯片文本（站点收完即清，视为成功）；`no-chip` = 都不满足。
3. Kimi/DeepSeek：先侦察它们的 📎 按钮 aria-label，补 `open`；若没有按钮则 `direct:true` + 补 `input`+`change` 事件。
4. 发送前清理：对每席 `input.files` 含「非本次要发文件」的，先 `inp.value=''` 清空（解决缺口 E）。
5. 谷歌：`prepare` 点 AI 模式 → `open` 点「添加文件和工具」→ 菜单精确命中「添加文件」→ chooser 塞文件；图片走「添加图片」。

**显式邀请推翻**：如果你认为「按站点 adapter」方向就错了（比如应该统一用合成拖放覆盖全部 9 家、不该维护按钮选择器），请直接说，我不需要「你这样挺好、建议微调」。也请指出草案里哪条会引入 O(N²) 或不可复现的坑。
