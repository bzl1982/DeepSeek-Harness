## 二、悬案裁决（谁说服了我）

### Q1 phase 状态机 → **定案：四相 + attention 正交（8/8 全票，含我方原推荐）**
`setup / running ⇄ paused / done`，attention 独立轴。全员增强后补三条铁律：
1. **轮次/阶段不进状态机**（全员一致）：loop 是 running 内的正交数据 `progress{round, limit, stage}`；tournament 5 阶段×3 轮、chairman 动态点名全部装得下——phase 必须粗才能统一，stage 必须细才能保真（文心）。
2. **done 带 doneReason 字段**（文心/通义）：区分"判据收敛 done✓"与"轮次耗尽 done⚠exhausted"，落盘首行 `# status: exhausted`——不拆新 phase，防误读为已完成。
3. **READY Gate 是 setup→running 的拦截边，不是驻留态**（ChatGPT/通义）：readiness=blocked|ready，Gate 检查项从各模式 `needs` **自动推导**，开始按钮物理 disabled（Agnes：不是弹窗警告后还能点）。
4. 进度文案不统一"第N/M轮"（ChatGPT/通义/文心）：build"不称第几轮"、chairman"第2次点名·动态终止"、上限要写"上限不是承诺"、用 roundNoun（次评审/次构建/轮点名）。

### Q2 工具面板 → **定案：全局右滑 tooldock，但通义的修正说服了我（8/8 支持全局右滑；主视图被我改判）**
- 我原推荐"绑定 activeSeat 作主视图"被通义**推翻**：题面"50 席 10 工具并发"恰恰是 activeSeat 绑定的失效场景——一次只看一席，用户要点 10 次才能看全，违背定案 11"聚合视图"精神。ChatGPT 的"双视角（全部活动+当前席位）"与通义殊途同归。
- **定案细节**：tooldock=`position:fixed` overlay 420px（**不违反横向禁令**——它不占布局、grid 一行 CSS 不变，文心/Agnes/豆包三家独立论证了这条例外）；默认视图=跨席位全局事件流（按席位分桶），activeSeat 只作过滤 chip；卡内只留 24px 定高状态行（🔧3·⚠1），点击=激活+预置过滤；**危险工具审批不进 tooldock，进 attention bar**（Kimi：审批必须"不点开席位也能看到"）；confirm 态才自动滑出（文心），calling/success 不抢焦点。
- 遗留实测项：webview 原生层是否盖住 overlay（通义/ChatGPT 都要求 CDP 实机验证，不许 CSS 猜；兜底=抽屉打开时 `.main{visibility:hidden}` 3 行）。

### Q3 外部 AI 回答 → **真分裂 6:3（DeepSeek 补评后 A 派+1），裁决 A+硬化（B 的抽屉基建随 tooldock 落地，v2 可迁）**
- **A 派（6）**：ChatGPT/豆包/文心/元宝/Gemini/**DeepSeek**。最强理由：**文心"回收是对照式操作"**——人工咨询时用户视线在网格里抄 9 个窗口的答案，右滑抽屉 360px 正好盖住要抄的那几扇窗；工具面板遮挡无所谓，回收面板遮挡致命。次强：ChatGPT"输入工作台≠监控工作台，不该共用容器；B 在编辑 4000 字时点席位→activeSeat 变→dock 换页=上下文争夺"；元宝"一边看工具结果一边写进回答框=焦点互斥灾难"；DeepSeek 补"B 在 50 席 micro 下盖住右侧几列，顶甲板只压顶部网格仍可见"+长文"弹出独立编辑窗"兜底（与文心⧉放大一致）。
- **B 派（3）**：Agnes/通义/Kimi。最强理由：通义"人工咨询让回收从间歇变全天高频，A 常驻顶甲板=每天每轮交纵向税；编辑锁盖不住 deck-summary 态要开始编辑的冲突"；Kimi"extbox 是长驻操作面，topdeck 是瞬态容器，长驻面放瞬态容器=每次折叠都做'锁or丢'选择题"。
- **裁决逻辑**：这是真 5:3，但两个决定性事实偏向 A——① 用户原话"挪到上面"；② 文心的"对照式操作"是**功能**理由而非偏好理由，直击人工咨询的真实动作（抄答案必须看网格）。同时 B 派的失效场景全部真实，所以 **A 必须带文心三条硬化**：编辑锁（focusin→data-editing 禁自动折叠，focusout 解除）+ max-height 限高内滚（绝不撑高甲板）+ **默认归属=activeSeat**（吸收 B 的席位绑定优势）。长文本给"⧉放大弹层"兜底。B 的 overlay 抽屉基建随 tooldock 一起落地，若未来人工咨询以长编辑为主，v2 一天迁完（通义/Kimi 都认可这个迁移成本）。

### Q4 API 虚拟滚动 → **定案：先原生，判据换"节点数"（8/8 全票先原生；数字分歧被通义消解）**
- 原生滚动+分组页签+密度档全员同意；**分组页签是强制默认不是可选项**（Kimi：不用分组的人会让分界线失效；文心：非当前组 display:none=天然软分页，API div 无 webview 红线）。
- **文心新知：固定行高是免虚拟化的前提**——重排元凶是"行高随内容自适应"，钉死 `grid-auto-rows` 后 50/100/200 席只差节点数不差重排量。
- **分界线裁决**：不采信任何家的席位数（100/120/150/200 都是拍脑袋），采信通义三条**可测判据**：活跃 DOM 节点 >8000 / 单帧 reflow >16ms / longtask >50ms（CDP+Performance API 实测）。超限先上通义**惰性展开历史**中间档（IO 只回收离屏席位的历史文本，名牌行常驻保 scrollIntoView——守住定案 23），真虚拟化是最后手段。
- Gemini 一击值得记录：虚拟化会让 `CDP DOM.setFileInputFiles` 找不到目标节点→发文件失败，与人工模式 R4 直接冲突。

### Q5 人工模式 → **定案：建模三（通道轴+快捷入口），但被两家修正了内核**
- **通道轴 per-seat（seat.delivery='auto'|'manual'）8/8 全票**，横切 11 种模式，支持混合（panel+网页 manual+API auto 合法）。
- **通义的 DispatchJob 降级链是本轮最佳架构洞见**：发给席位的内容+附件抽象成 DispatchJob，auto/manual 是同一 Job 的两个 executor，**auto 失败自动降级 manual**（不是重试到死，不是平行系统）——代码复用最大化的正解。
- **文心修正 R1（必须采纳）**："同一份稿发所有人"在 review（防锚定）/debate（防自我强化）/tournament（匿名+定序）/transparent（除自己外）下是**错的**——分发必须按 mode+stage+seat 生成 **per-seat view**，剪贴板与 CDP 只是投递通道不同，view 生成模块共用。
- **ChatGPT 三态追踪**："已发≠已答≠AI收到"，dispatchState/replyState/fileState 独立（含文件逐席位状态）。
- 入口形态小分歧（进 mode 下拉 vs 独立按钮）：4:3 略偏独立按钮（ChatGPT/通义/文心/Agnes），且 Kimi 自己说"轴必做、工作台可砍"。**裁决：独立"人工咨询"入口 + 不占用 mode 枚举**（豆包/Gemini 的"第 12 种 mode"表述不采纳，但它们的分发追踪面板设计可并入）。
