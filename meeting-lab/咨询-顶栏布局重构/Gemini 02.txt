### 尺寸与折叠优先级规则

在屏幕纵向高度受限时，必须通过 JS 监听 `window.innerHeight` 并依序追加 CSS 类来被动折叠，优先级如下：

1. **优先折叠 `.extbox**`：它是间歇性录入表单，不录入时高度价值最低。


2. **其次缩小 `.logdock**`：从 32% 降维至 20%，若还不够则彻底折叠至 28px（仅留标题）。
3. **最后折叠 `.modezone**`：将其收拢进 `.topdeck.is-collapsed` 的单行摘要中（采纳 ChatGPT 方案的变体）。


4. **底线**：`.header` 与折叠后的摘要行（含 `chairbar` 的暂停/停止）永不折叠。



**成本与反例**：

* **成本**：低。折叠全部基于 `height: 0` 和 `overflow: hidden`，仅变更父容器 CSS，绝不触发 `.grid` 内的 DOM 卸载，保证测试全绿。


* **反例**：绝对不要在 `.grid` 及其祖先元素上使用基于 JavaScript 窗体 Resize 事件的重排计算。每次 Resize 重新计算宽高并强赋给 `<webview>` 会导致极为严重的 IPC 通信卡顿。

## Q2：席位规模化 (12 → 50+) 的组织方案

本测试台席位包含上限 9 个的重 `<webview>`，以及数量无上限的轻量 API div。必须利用这种不对称性。

### 方案：原生滚动 + 自适应网格密度

1. **网格组织 (虚拟滚动是毒药)**：
* 在 `.grid` 容器上使用原生 `overflow-y: auto`。由于 `<webview>` 最多 9 个，其余全是轻量 `div`，50 个 DOM 节点在 Electron 下毫无渲染压力，完全不需要虚拟滚动技术。




2. **下拉升级 (密度档位)**：
* 废弃硬编码的「每排 3/4/5/6」。改为**视图密度下拉 (`.seatctl .density-select`)**：包含「舒适 (Comfort)」、「紧凑 (Compact)」。


* **字段级实现**：通过给 `.grid` 赋予 CSS Grid 的 `auto-fit` 与变量控制：
```css
.grid {
  display: grid;
  /* 舒适态 --cell-min 为 320px，紧凑态为 240px */
  grid-template-columns: repeat(auto-fit, minmax(var(--cell-min), 1fr));
}

```




3. **角色组去固定席位化 (动态模分配)**：
* 废弃固定席位数匹配。当 `N`（总席位）> `R`（角色模板数）时，采用取模轮替分配：`role = roles[index % roles.length]`。


* 若某角色为组长，仅在 `index < roles.length` 且判定为 leader 时赋予。



**成本与反例**：

* **成本**：极低，移除了复杂的行列重排 JS 代码，全部交由 CSS Grid 引擎。
* **反例**：**绝对不要使用虚拟滚动 (Virtual Scrolling)**。虚拟滚动会在元素滚出视口时将其从 DOM 树卸载，这将直接摧毁内部的 `<webview>` 进程并丢失登录态。

## Q3：网页与 API 席位工具能力的 UI 对齐

要在壳层实现工具 UI，必须采用**绝对定位覆盖**方案，避免干涉 `webview` 内部结构。本测试台有 200+ 对标 WorkBuddy 的工具。

### 信息架构与工具交互流

1. **席位卡片统一头部 (`.cell-head`)**：
* 移除后缀标签差异。左侧：角色名/公司名；右侧：状态胶囊 (`.status-pill`)。
* 工具调用中：胶囊显示为 `⚡ [工具名] 运行中...`，背景闪烁。


2. **工具面板位置 (`.tool-drawer`)**：
* 作为一个 `div` 置于 `.cell` 内，与 `<webview>` 平级，设置 `position: absolute; bottom: 0; width: 100%; z-index: 10;`。
* 当该席位调用工具或需确认参数时，`.tool-drawer` 从卡片底部向上滑出，盖住该席位的下半部分。


3. **权限控制UI**：
* 顶栏 `.chairbar` 增加一个全局按钮：`[⧉ 工具白名单]`。
* 点击弹出一个壳层的全局 Modal，采用多选框矩阵分配 200+ 工具给 50+ 席位。默认状态：仅对 API 席位开放全部，对 Web 席位开放只读类工具（检索/读文件）。



**字段级设计 (HTML 片段)**：

```html
<div class="cell" data-type="web"> <!-- 或 data-type="api" -->
  <div class="cell-head">
    <span class="name">ChatGPT (法律专家)</span>
    <span class="status-pill active" data-tool="file-read">⚡ 读文件中</span>
  </div>
  <webview src="..." class="content-view"></webview> <!-- API 则是 div.content-view -->

  <!-- 工具抽屉，仅在调用时增加 .is-open -->
  <div class="tool-drawer">
    <div class="tool-title">调用：检索文献</div>
    <div class="tool-result">已找到 3 份文件。是否允许回注？ [允许] [拒绝]</div>
  </div>
</div>

```

**成本与反例**：

* **成本**：中等。需要管理 `.tool-drawer` 的 `z-index` 层级，并处理工具执行引擎到 UI 的状态同步。
* **反例**：**切勿将工具调用的过程和结果统一输出在底部 `.logdock` 中**。50 个席位并发调用工具会形成信息瀑布，用户根本无法分清是哪个席位调用的哪个工具。必须将工具 UI **局部收敛**在调用它的 `.cell` 内部。

## Q4：模式 × 阶段映射表 (`MODE_CONTROLS`)

测试台包含 8 种会议模式。通过 `data-mode` 和 `data-phase` 双键驱动固定 DOM 的显隐。

| 模式 (`data-mode`) | 开会前 (`data-phase="pre"`) 需显示 | 开会中 (`data-phase="run"`) 需显示 | 模式核心设计意图 |
| --- | --- | --- | --- |
| `transparent` (透明广播)

 | `#tmbox`, `#extbox` | `#extbox` | 重视外部干预，`#tmbox` 仅配置期可见 |
| `panel` (专家会诊)

 | `#groupbox`, `#extbox` | `#extbox` | `groupbox` 用于确定会诊分组 |
| `build` (工程交付)

 | `#buildlevel` | `#buildlevel` (只读态) | `buildlevel` 需要在会中持续验证 |
| `relay` (顺序接龙)

 | `#orderbox` | `#turn-indicator` | `orderbox` 定顺序，会中显示高亮指示器 |
| `debate` (辩论)

 | `#factionbox` (阵营划分) | `#timerbox` (倒计时) | 阵营配置仅在会前有效 |
| `cross-exam` (质证)

 | `#evidence-upload` | `#current-evidence` | 上传与展示分离 |
| `group-consult` (分组会诊)

 | `#sub-room-config` | `#room-switch` (切房器) | 涉及多层级嵌套关注点 |
| `open` (开放讨论)

 | (最简态，仅显示基础配置) | (最简态) | 降低控制栏干扰，最大化网格 |

**维护策略（防失控）**：

* 所有组件的 DOM 都在 `index.html` 中硬编码存在（满足固定 DOM 原则）。


* 在 CSS 中，默认隐藏所有专属模块：`.modezone > div { display: none; }`
* 精准匹配显隐（字段级）：
```css
/* 透明广播模式下，在 pre 阶段显示 tmbox */
.topdeck[data-mode="transparent"][data-phase="pre"] #tmbox { display: flex; }
/* 暂停/停止按钮的置灰逻辑 */
.topdeck[data-phase="pre"] .chairbar .btn-pause { opacity: 0.4; pointer-events: none; }

```



**成本与反例**：

* **成本**：极低。只需在 JS 改变模式或点击「开始会议」时，修改 `.topdeck` 的两个 `dataset` 属性即可。
* **反例**：不要将映射表写在 JS 中去动态 `document.createElement()`。那样不仅会破坏原生的 `node --test` 断言（因为 DOM 节点会短暂消失），还会导致之前绑定的事件监听器丢失，必须使用静态 DOM + CSS 切换。
