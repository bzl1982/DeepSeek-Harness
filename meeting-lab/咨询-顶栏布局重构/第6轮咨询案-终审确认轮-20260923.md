## §1 技术负责人的合成裁决草案（本轮请 9 家攻击它，攻击成立我改，不成立即冻结）

这不是和稀泥，是把第 5 轮全部新事实（F1~F4）+ 全部预承诺判据收拢成一条**可执行、可证伪**的终审规则：

**R1（Q3 终审规则）**
- 默认 A（T0 手动为主 + 分发半高频 + 7:1），**切换器必须可见**：`.header` 右侧常驻「布局：甲板⇄抽屉」切换（采纳元宝条件，破默认惯性）；
- **F1 补丁升级为硬性要求**：追踪表/编辑体展开一律走 absolute 浮层（`data-editing` 或手动展开均可），**任何展开形态都不得挤压网格行高**——这同时满足通义的"第三态"钉死条件（他原话："A 下 running 态点每席回收按钮必须不压网格底排——做不到就翻 B"）；
- 遥测六指标全埋点：externalPanelOpenCount / EditDuration / manualRecoveryCount / autoRecoveryCount / manualCorrectionCount / dockSwitchCount + 分发半操作时长（元宝）+ editingInRunningRatio（DeepSeek），**按动作级计数**（Agnes），**N≥20**；
- **三个翻 B 触发器**（任一满足即翻，机械动作不辩论）：① Precision=100% ∧ Recall≥80% ∧ 手动<20%（ChatGPT）；② 分发半手动操作日均>30min（元宝）；③ 通义判据实测成立：存在"需逐席点操作但浮层方案挡住目标席位"的时段且无法用浮层消除；
- 通义 F3 批判的消解：默认惯性靠"可见切换器 + dockSwitchCount 埋点 + B 派预测（T0 纵向税真实存在→遥测会翻）"三方制衡；若 B 派预测错误，是数据推翻 B 派，不是规则封印 B 派。

**R2（Q4 双半落位终审）**
- **一个逻辑组件、一份状态**（DispatchJob 三态 + dispatchTrack 表共用，8 家零分歧）；
- 默认落位 = 顶甲板（A），内部**双页签「分发」「回收」**（豆包/Agnes/文心方案）；组件支持整体搬移到右 dock（逃生舱的 CSS 切换，文心同节点方案，复用率 100%）；
- **单席深读/工具详情走 tooldock，与双半面板彻底分开**（Agnes 切割，纠正 ChatGPT/DeepSeek/元宝把两者混装）。即：R2 实际形态 = 通义"一个容器两页签" × 文心"落位可切换" 的交集，hybrid 之争（分发顶/回收右分置）**不采纳**——采纳 Agnes 的数据流论证：同一条数据流拆两个物理位置是 muddle。

**R3（P0 顺序，采纳 §0.4 集体共识）**
1. **分发半手动兜底先行**（用户当下最痛：发不出去）——DispatchJob 三态 + L1/L2/L3 降级 + 已发 k/N 进度 + 失败席位显式点名；
2. 自动回收抽取器（selector∧增量游标∧稳定窗口）**并行做真机验证**（5 家 DOM，验证不过的 provider 自动降级手动，不阻塞 ship）；
3. R5 产物契约（索引+覆盖度红字点名+逐席原话）随回收半落地。

**R4（开工闸门冻结件）**：四 phase / readiness / step / round / attention / deliveryChannel / artifact.kind 七字段；删 380px side；TopDeck/Grid/LogDock/ToolDock 四容器；50+ 席策略；角色组任意人数；Web/API 同构 SeatCard；人工咨询独立入口；READY Gate；透明广播 23 条意外兜底（ChatGPT 补的 22/23 并入）。
