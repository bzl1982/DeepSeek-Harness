## §5 【新需求】人工模式（用户原话与现状）

**用户原话**："是否有人工模式呢？就像我现在手动复制过去咨询，我现在每次都一个一个窗口贴文字或上传文件，非常不方便，因为现在的广播发文件功能用不了。"

**现状事实（已核源码/实测）**：
- 测试台已有主持人栏：📢广播（空闲=直接发网页/API；会议中=汇编进下一轮）、📎发文件（网页=CDP `DOM.setFileInputFiles`，API=文字告知文件名）——**真机实测不可用/不可靠**（网页输入框是 Quill 时 Enter 无效已修，但上传链路与完成检测仍有失败场景：`File.path` 已废弃需 `webUtils.getPathForFile`、上传 ok 未检查会静默失败、图片/PDF 只 push 文件名占位符）。
- 用户今天的真实咨询流：写好咨询稿 → 逐个窗口手动粘贴/传文件 → 逐个窗口把回答复制回来 → 人工汇总。9 个窗口逐个操作，没有进度追踪、没有回收归档。
- 已有"外部 AI 回答"面板能做**回收**（粘贴回来、自动剥标注、参与上下文切片），但**分发侧完全没有人工辅助**。

**设计要求（R1~R4）**：
- R1 分发：一份咨询稿 + N 个附件发往 M 个选中席位。自动通道失败时，手动兜底必须顺滑：每席位一键"复制到剪贴板"→ 用户粘贴 → 标记已发；进度 已发 k/M；未发清单。
- R2 回收：每席位"已回答"标记（手动勾选或 DOM 自动检测）；回答回收进会议记录；未答名单一目了然。
- R3 与会议引擎的关系：人工模式不跑自动轮次、不依赖完成检测（人自己判断）；但落盘格式复用（round-N.md / 会议记录.md）。
- R4 文件：手动=每席位文件选择器预填同一批文件；自动=CDP setFiles + 逐席位状态回报（成功/失败/重试）。

**Q5 的核心建模题（必须选边）**：
- 建模一：人工模式 = **第 12 种 mode**（进模式下拉，状态机照走，只是"发言者=人"）；
- 建模二：人工模式 = **横切所有模式的"投递通道"**（每个席位 auto/manual 二选一；人工咨询=全 manual 的退化形态，不占 mode 位）；
- 建模三：两者都要（通道是底层，另设一个"人工咨询"快捷模式 = 全 manual + 分发追踪面板）。
请选边并论证：哪种建模让"开会"与"人工咨询"共用最多代码、状态机最不别扭、用户心智最简单？
