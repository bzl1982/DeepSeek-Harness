## §1 一句话现状

一个 Electron 桌面会议测试台，主区域是 **12 个席位网格**（9 个 `<webview>` 真网页 AI + 3 个 API 席位 div），上方有顶栏（模式/角色组/议题/开始）、流程说明、模式场景卡；**右侧有一条恒定 380px 的竖栏**，里面放了「外部 AI 回答」「透明广播设置」「会议日志」「摘要」。用户发现：折叠右栏里的面板只是把内部内容 `display:none`，**380px 列宽一点没少**，等于白折——要求把这些非窗口功能全部改成「可真正折叠腾空间」并挪到顶部，且布局要随会议模式变化。

## §2 现状事实清单（逐条，已核源码；外部 AI 可跳过不重复答）

> 全部来自 `meeting-lab/shell/index.html`，附行号。外部 AI 不需要重新分析这些，只需在它们基础上回答 §0。

1. **整体骨架**（`index.html:8-9, 18`）：`body` 是 `display:flex; flex-direction:column; height:100vh; overflow:hidden`。子元素从上到下：`.header` → `.flowwrap`（含 `.flow` + `#flow-toggle`）→ `.scene` → `.main`。
2. **`.main` 是横向 flex**（`index.html:18`）：左 `.left`（`flex:1`）+ 右 `.side`（`width:380px; border-left`）。
3. **`.left` 内容**（`index.html:124-125, 179-206`）：`.seatbar`（`#seat-chips` 参会芯片 + `.seatctl`[角色组下拉 / 重排角色按钮 / 每排窗口数下拉 3·4·5·6]）→ `.chairbar`（主持人输入 + 📢广播 + 📎文件 + 发文件给所有人 + ⏸暂停 + ⏹停止）→ `.grid#grid`（12 个 `.cell`）。
4. **`.side` 右栏内容**（`index.html:96, 208-248`）：`.extbox`（外部 AI 回答，`.head` 点开切 `.open` 类→`.body` `display:block`）→ `#tmbox`（透明广播会议设置：输出目录/轮数/议题资料）→ `h2#log-head`（会议日志标题，点击切换）→ `.log#log`（`flex:1; overflow-y:auto` 滚动文本）→ `.summary`（摘要）。
5. **根因（用户投诉点）**：`.side { width:380px }` 是固定列宽（`index.html:96`）。`#log-head` 点击只做 `logEl.style.display='none'` + `summaryEl.style.display='none'`（`index.html:872-877`）；`extbox` 折叠只切 `.body` 的 `display`（`index.html:137-138`）。**两者都只藏内部内容，`.side` 的 380px 宽度永不变化** → 网格永远拿不回这 380px。这就是「占空间没意义」。
6. **对照：顶部 `流程/模式说明` 折叠是「好的」**（用户没投诉它）：`#flow-toggle` 切 `body.infocollapsed`（`index.html:868-871`）；CSS `body.infocollapsed .flow{min-height:0;padding:2px} .flow .ph{display:none} .scene{display:none!important}`（`index.html:73-75`）。即整段 `.scene` 消失、`.flow` 压成一条缝——**纵向空间真回收**。可复刻此机制到新顶栏。
7. **12 席位里有 9 个 `<webview>`**（`index.html:25` `.cell webview{flex:1}`）：Electron 的 `<webview>` 是独立渲染进程、很重。**任何布局改动都不能卸载/重建这 12 个 cell**，只能改它们的容器尺寸/位置，否则会重新加载 9 个网页 AI（丢登录态、卡顿）。
8. **模式感知已部分存在**（`index.html:1700, 1776-1777, 1710-1773`）：`tmbox` 仅 `transparent` 模式显示；`产物验证` 档位仅 `build` 模式显示；`renderScene()` / `renderFlow()` 按模式渲染不同说明。说明「按模式显隐控件」在工程上可行，只是目前只做了两处。
9. **主持人栏语义双态**（`index.html:195-204, 843-863`）：📢广播在「开会中」=`runningTM.pushChairMessage`（汇编进下一轮提示）；空闲时=直接发给网页/API。⏸暂停/⏹停止在空闲时 `disabled`。即 chairbar 控件在两种状态下可用性不同。
10. **技术栈**：Electron renderer（`nodeIntegration` 开，`require()` 直接用 core 模块）；纯原生 CSS（flex + grid）+ 原生 JS，**无框架**；`disable-gpu` 强制开启（仅影响截图，不影响布局）；`node --test` 400 用例全绿（布局改动需保持测试不破）。

## §4 我识别出的缺口（供证伪或确认；每条带证据）

- **G1（核心，已证）**：`.side` 恒定 380px 是空间浪费源。证据：`index.html:96` `width:380px` + `index.html:872-877` 折叠只动 `display`。→ 必须让右栏整体可消失，或干脆删除右栏、把内容迁到可折叠的顶/底区域。
- **G2（风险）**：9 个 `<webview>` 不能被布局改动卸载。证据：`index.html:25` + 实测 9 webview 同渲染才稳定（历史闪退修复靠 `--disable-gpu`）。→ 任何「折叠腾空间」方案若触发 cell 容器 `display:none`→再显示导致的 webview 重建，都会丢登录态。需用 `width/height/flex` 收缩而非 `display:none` 整容器，或对 cell 用 `visibility`/绝对定位保留。
- **G3（设计空白）**：会议日志是**开会时持续滚动**的参考文本，外部 AI 回答是**间歇录入**的表单——两者使用节奏不同，统一塞进同一个「顶部甲板」未必最优。证据：`.log` `flex:1;overflow-y:auto`（持续追加 `log()` 调用，`index.html:1657` 清空按钮）。→ 需外部 AI 判断日志放顶 vs 底更合理。
- **G4（已具备基础）**：模式感知显隐可行但零散。证据：`index.html:1700/1776`。→ 应体系化成一个「模式→控件组」映射，而非逐个 `if`。
- **G5（交互语义）**：chairbar 在空闲/开会双态，若挪进顶栏需明确「开会时才需要暂停/停止」还是「常驻」。证据：`index.html:203-204` 空闲 `disabled`。
- **G6（一致性）**：现有折叠有两套机制（顶部 `body.infocollapsed` 整段收；右栏 `display:none` 内部收），行为不一致。重构应统一成一种「真腾空间」机制。

## §5 问题清单（§0 的展开版，每题含我的倾向 + 疑问）

- **Q1（最重要，我下一步就要改代码）**：我倾向**删掉固定右栏 `.side`**，让 12 格网格占满整宽；把所有控制/信息面板收进一个**可整体折叠的顶部「控制甲板」**（用 §2-6 那种 `body.infocollapsed` 式整段收，而非只藏内部）。疑问：顶部甲板在「开会中日志狂滚」时会不会和网格抢纵向空间？是否该把日志单独放**底部停靠条**？
- **Q2**：我倾向——外部 AI 回答放顶部甲板里（它是表单，间歇用）；会议日志放**底部全宽停靠条**（折叠成 1 行标题，展开占底部 30%~40%）。疑问：底部停靠条展开时会不会压住网格底边、和 cell 的「底边拖高」(`dragCellHeight`) 冲突？
- **Q3**：我倾向做一个 `MODE_CONTROLS = { transparent:['tmbox','chairbar','log','extbox'], panel:['group','log','extbox'], build:['buildlevel','log'], ... }` 映射，顶栏按 `currentMode` 渲染对应组。疑问：是否该区分「开会前配置组」与「开会中监控组」分两个阶段显示，避免控件一次全堆出来？
- **Q4**：我倾向折叠用 **flex 容器整体 `min-height:0`/高度收为 0 + 内部 `overflow:hidden`**，对 webview 网格区只用 `flex`/`grid` 尺寸收缩、绝不对 12 个 cell 用 `display:none`。疑问：顶部甲板折叠时，若用 `display:none` 收甲板本身（不含 cell），会不会误伤？甲板里有没有 webview？——答：甲板里**没有** webview（只有表单/文本），所以甲板自身可安全 `display:none`。
- **Q5**：我倾向 chairbar **常驻顶栏**（广播/发文件随时可用；⏸⏹ 开会时才 enabled），因为它本就是「主持人操作」入口，不属于「会议日志/外部回答」那类信息面板。疑问：这样顶栏会不会在空闲时显得控件过多？是否该把 chairbar 拆成「配置期隐藏、开会期显示」？

## §6 我的初步草案（请当靶子批判；方向错了请直接推翻）

**目标布局（草案 v0）**：

```
body (flex column, 100vh)
├─ .header            （不变：模式/角色组/议题/开始会议/清空日志）
├─ .topdeck           【新增，可整体折叠】控制甲板，按模式渲染不同控件组
│   ├─ .seatbar       常驻：参会芯片 + 角色组/重排/每排窗口数
│   ├─ .chairbar      常驻：主持人广播/发文件/⏸/⏹（⏸⏹ 开会时 enabled）
│   ├─ .modezone      模式专属：tmbox(transparent)/buildlevel(build)/group(panel)/flow/scene
│   └─ .extbox        外部 AI 回答（折叠表单，间歇用）
│   （折叠：整个 .topdeck 收成一条「▴ 展开控制甲板」标题栏，真腾纵向空间）
├─ .main (flex:1, 现在只有左，无右栏)
│   └─ .grid          12 cell，占满整宽
└─ .logdock           【新增，底部】会议日志 + 摘要，全宽，折叠成 1 行标题
```

**关键机制**：
- 删 `.side`，`.main` 不再分左右，`.grid` `flex:1` 占满。
- `.topdeck` 折叠复用 `body.infocollapsed` 思路：收起时 `.topdeck{min-height:0;height:0;overflow:hidden}` 或整段 `display:none`（甲板内无 webview，安全）。
- `.logdock` 底部停靠：默认展开占 `flex:0 0 32%`，点标题收成 `flex:0 0 28px`（只留标题行），网格自动补满。
- 模式映射 `MODE_CONTROLS` 决定 `.modezone` 渲染哪些子块；`renderDeck()` 在 `selMode.change` 时重渲染（复用现有 `renderFlow/renderScene` 思路）。

**我邀请你推翻的点**：
- 如果你认为「会议日志根本不该在底部、或外部 AI 回答不该在顶」，直接说，并给替代落位。
- 如果你认为「删右栏 + 顶部甲板」整体方向就错（例如该用**侧边 overlay 抽屉**：平时 0 宽、点按钮滑出覆盖在网格上、不永久占布局宽度），请直接推翻，我不需要「你这样挺好、建议微调」。
- 如果你认为模式感知不该用「显隐组」而该用「向导式分步」（开会前一步、开会中一步），也请直说。
