## §2 分歧点（技术负责人拍板，不交下一轮）

**分歧 A｜L1 是否按站点分主备**
- 3 家（ChatGPT/元宝/Gemini/DeepSeek）主张「Gemini/元宝/豆包 L1 优先尝试，其余 L2 起手」；
- 2 家（谷歌搜索/文心）主张「全局 L2 起手、L1 仅静默异步」。
- **拍板（采纳 Agnes 精确版）**：
  - `L1_WHITELIST = {Gemini, 元宝, 豆包, 通义, 文心, ChatGPT}` → **试一次 + 强制回读校验**，过则成功、不过秒降 L2；

  - **L1/L2 必须是两条独立代码路径**（`if(白名单){tryL1(); if(回读通过)return;} L2();`），**严禁 `try{L1}catch{L2}` 结构**——F7-4 证明 L1「静默成功」不抛异常→不进 catch→不降 L2→席位被标「已发」实则空。

**分歧 B｜闸门丙回退形态**
- 多数说「独立浮窗」；元宝说「主列内嵌」；Agnes 说「同节点 CSS 浮层」。
- **拍板（采纳 Agnes，Fixed 决策3 合规）**：回退 = **`#dispatchdeck` 的 `.dd-body` 同节点 CSS 切换**（从顶甲板内 `left:0;right:0` 改为 `right:0;left:auto;width:420px` 钉视口右侧），**同一 DOM、同一渲染进程、零新 webview**。严禁 `new BrowserWindow()`（违固定决策3 + 闸门乙）。顶甲板永空：保留广播控制/席位状态/k-N/失败点名/唤起浮层入口。

**分歧 C｜F1 浮层 vs LogDock 层级（新增）**
