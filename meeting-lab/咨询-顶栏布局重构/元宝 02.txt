为什么这样设计

1. 顶部两层上限（.header + .topdeck）：Kimi 第 1 轮指出 .flow/.scene 应降级为 modezone 子成员。原因：顶栏超过两层会导致纵向空间碎片化，12 个 webview 被压得无法操作。
2. .topdeck 用 display:none 而非 height:0：甲板内无 webview，彻底移除 DOM 渲染可释放 GPU 合成层（disable-gpu 下尤其重要）。
3. .logdock 用 flex 收缩而非 display:none：日志需保持滚动状态（自动跟随暂停/恢复），display:none 会丢失滚动位置。
4. 网格永不 display:none：9 个 <webview> 是重资源，卸载重建会导致登录态丢失、CDP 连接断开——对 400 测试是灾难。

成本与反例

决策 成本 反例（什么时候不该这么做）

display:none 甲板 零重排（直接移除渲染）；测试: 需断言 .topdeck 内节点存在性而非可见性 如果甲板内含 webview 则绝对不可用——但本设计已确保甲板内无 webview

字段级设计：

容器 class 状态键 尺寸

分组页签栏 .grid-tabs data-active-group="web" flex:0 0 36px

虚拟滚动视口 .grid-viewport data-density="standard" flex:1

为什么：
• 分组页签：50+ 席位同时渲染 50 个卡片（即使 API 是轻 div）仍会导致 DOM 节点过多、CSS 重排卡顿。分组后每组 8-15 个，可控。

• 虚拟滚动：API 席位 div 虽轻，但 50+ 同时渲染 + 工具调用动画仍会卡。虚拟滚动只渲染视口内 + 缓冲，DOM 节点恒定在 20 个以内。

• 密度档位：用户可能需要一眼扫 50 个席位的响应状态（紧凑模式），也可能需要仔细阅读某个席位的工具调用结果（宽松模式）。

2.2 「每排 N 个」下拉升级

现状问题：硬编码 3/4/5/6，列数最多算到 4 列。

升级方案：
// 自动计算列数
function calcColumns(seatCount, viewportWidth, density) {
  const cardWidth = { compact: 160, standard: 240, relaxed: 320 }[density];
  const gap = 8;
  const cols = Math.floor((viewportWidth + gap) / (cardWidth + gap));
  return Math.max(2, Math.min(cols, 8)); // 下限 2，上限 8
}


UI 控件：下拉改为 [自动│2│3│4│5│6│8] + 密度档位独立按钮。自动模式监听 ResizeObserver 实时重算。

成本：DOM 无新增；状态: auto-columns 布尔 + density 三态；重排: ResizeObserver 回调触发 relayout()。

反例：如果用户在 4K 屏上强制 6 列，卡片会被拉得极宽，webview 内容变形。不该在宽屏上限制最大列数过低。

const PHASE_KEYS = {
  pre: 'config',    // 开会前：配置阶段
  running: 'active'  // 开会中：活跃阶段
};

// 映射表结构
const MODE_PHASE_MAP = {
  transparent: {
    pre: ['tmbox', 'seatbar', 'extbox'],
    running: ['chairbar', 'logdock', 'tool-console']
  },
  panel: {
    pre: ['group', 'seatbar', 'extbox'],
    running: ['chairbar', 'logdock', 'tool-console', 'round-indicator']
  },
  // ... 其余 6 种
};


映射表随模式增长不失控的策略

1. 双键索引：MODE_PHASE_MAP[mode][phase] → 控件组数组。新增模式只需加一个 key，不影响其他模式。
2. 控件组复用：.seatbar、.chairbar、.logdock 是所有模式共享的基础组，不重复定义。
3. modezone 渲染函数：renderModezone(mode, phase) 根据映射表决定渲染哪些子块，避免零散 if。
4. 测试友好：映射表是纯数据，400 测试可直接断言 MODE_PHASE_MAP.transparent.pre.includes('tmbox')。

反例：如果每种模式写一个独立的渲染函数（8 个函数），新增模式需复制粘贴大量代码，映射表失控。不该用函数散弹代替数据驱动。
