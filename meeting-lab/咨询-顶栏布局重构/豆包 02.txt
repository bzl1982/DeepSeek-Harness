# 第2轮 测试台整体UI设计方案

基于第1轮共识基线扩展，完整覆盖席位规模化、工具能力对齐、模式映射三大新增需求，所有设计均附带决策依据、实现成本与约束反例。

## Q1 完整UI设计方案

### 核心结构

沿用共识基线的四层垂直架构，所有区域均支持折叠/展开，纵向折叠优先（符合webview高度重排开销远低于宽度的性能约束）。

#### 容器层级（字段级）

```
.app-container (flex-col, h:100vh)
├── .header (flex: 0 0 40px, 常驻)
├── .topdeck (flex: 0 0 auto, 可折叠)
├── .grid-container (flex: 1, 核心区, 含席位网格)
└── .logdock (flex: 0 0 auto, 可折叠)
```

#### 折叠优先级规则（屏幕高度降低时依次触发）

1. **第一优先级：.topdeck 折叠**（展开 max-height: 35vh → 折叠 28px 单行摘要）
2. **第二优先级：.logdock 高度压缩**（展开 32% → 20% → 折叠 28px 单行摘要）
3. **第三优先级：Grid 密度提升**（卡片内边距缩小，每排数量自动+1）
4. **最低优先级：Grid 尺寸压缩**（仅被动响应flex收缩，webview永不卸载）

> 
> 为什么：TopDeck是间歇交互区（配置、外部提问），LogDock是辅助查看区，Grid是会议核心载体且webview resize有性能成本，按「非核心→核心」顺序折叠，保障主体体验。

## Q2 席位规模化方案（12→50+ 无上限）

### 核心设计：三级弹性网格体系

利用「webview最重仅9个、API席位轻量可无限」的不对称性，实现无上限扩展。

#### 1. 网格组织方式

- **分组标签页**：按角色组/类型（网页/API）分组，顶部组标签切换，默认「全部视图」；解决50+席位单屏无法全览的问题。
- **虚拟滚动**：仅渲染视口内约20-30个席位卡片；9个webview席位永远全量常驻DOM（不参与虚拟销毁），API席位动态创建销毁（轻div，成本可忽略）。
- **密度档位**：紧凑/标准/宽松三档，调整卡片内边距与信息密度，对应每排数量自动适配。

#### 2. 「每排N个」下拉升级

- 默认**自动计算**：`cols = Math.floor(容器宽度 / (卡片最小宽度 + 间距))`，范围2~12列，随窗口宽度实时自适应。
- 手动下拉保留并扩展为 `2/3/4/5/6/8/10/12` 档，选择后覆盖自动计算。
- 状态键：`ui.grid.colsMode`（auto|manual）、`ui.grid.manualCols`、`ui.grid.density`（compact|normal|loose）

#### 3. 角色组去固定席位化

- 角色组定义从「固定席位数」改为「最小席位、最大席位、优先级」三维配置。
- **分配规则**：按优先级从高到低，先满足所有角色组的最小席位，剩余席位按优先级比例分配。
- **超编轮替**：总席位超过角色组最大席位总和时，自动开启「轮替模式」，同组内席位轮流激活（非激活席位待机，不占用计算资源）。
- 组长机制：每个角色组默认第1个席位为组长，支持手动指定。

### 成本与反例

| 维度 | 成本说明 | 反例（禁止这么做） |
| --- | --- | --- |
| DOM | webview席位永远常驻（9个上限），API席位虚拟滚动动态增删，DOM峰值稳定在30左右 | 禁止全量渲染50+webview：受9个上限约束，且内存会爆炸，Electron进程直接崩溃 |
| 状态 | 新增分组、密度、虚拟偏移、轮替状态共5个，状态复杂度中等 | 禁止纯分页方案：割裂会议整体感知，无法跨页对比输出，不符合会诊/辩论模式需求 |
| 重排 | 虚拟滚动下仅视口内卡片重排，50席重排成本与12席相当 | 禁止固定每排数量：宽屏浪费空间、窄屏溢出，适配性极差 |
| 测试 | 新增虚拟滚动边界、分组切换、轮替逻辑测试约30个用例 | 禁止webview参与虚拟销毁：重载成本极高，且登录态、页面状态全部丢失 |

## Q3 网页席位工具能力对齐方案

### 核心原则：工具UI全在壳层，零侵入webview内部

### 1. 席位卡片信息架构统一

- **统一标识**：卡片标题栏格式为「角色名 · 模型/来源 + 类型图标」，移除`-API`后缀与公司名区分；🌐代表网页席位，⚡代表API席位。
- **统一结构**：标题栏 + 内容区 + 底部工具条；内容区webview/聊天输出差异化，底部工具条完全一致。
- 卡片class：`.cell`（基础） + `.cell--web`/`.cell--api`（类型） + `.cell--tool-open`（工具抽屉展开）

### 2. 工具面板位置：两级架构

- **席位级工具抽屉**：每个席位底部可上滑拉出（默认收起，展开占卡片高度30%），显示可用工具列表、调用历史、结果预览；上下文最强，不遮挡其他席位。
- **全局工具台**：TopDeck内新增「工具箱」标签页，聚合所有席位工具调用状态，支持批量启停；适合全局管理。

> 
> 为什么：工具调用是席位级行为，卡片内抽屉上下文最匹配；全局汇总满足批量管理需求；完全在壳层实现，不触碰webview内部。

### 3. 工具调用交互流

1. **触发**：壳层监听webview内容识别工具调用指令，或用户手动在抽屉选择工具。
2. **执行中**：卡片标题栏显示状态（🔄 调用中：文件检索），抽屉内展示参数与进度。
3. **结果返回**：抽屉内显示结果预览（成功/失败/摘要），壳层自动将结果以文本形式注入webview。
4. **确认机制**：默认自动回注，可配置「用户确认后发送」，确认按钮在抽屉内。

### 4. 权限控制

- 配置入口：TopDeck「角色配置」标签页，按角色组设置工具白名单。
- 默认权限：API席位默认开启基础工具（文本检索、文件读取），网页席位默认全关（安全优先），需手动开启。
- 状态键：`session.groups[].toolWhitelist`、`session.seats[].toolsEnabled`

### 5. 并发调用防刷屏

- 日志聚合：LogDock内多条工具调用合并为「[10:05] 3个席位并发调用文件检索」，点击展开详情。
- 席位隔离：工具输出仅在自身抽屉内显示，不注入主聊天区。
- 全局通知：右上角toast提示完成，不占用主界面空间。

## Q4 模式 × 阶段映射表

### 完整映射表（8种模式 × 2个阶段）

所有控件通过 `data-mode` + `data-phase` CSS属性选择器驱动显隐，固定DOM不动态增删。

| 模式（data-mode） | 开会前（data-phase: pre） | 开会中（data-phase: in） |
| --- | --- | --- |
| **transparent**   透明广播 | 主持人栏：模式选择、席位配置、广播开关、开始按钮   TopDeck：角色配置、参数设置   暂停/停止：隐藏 | 主持人栏：广播按钮（📢广播中）、结束按钮、音量   TopDeck：折叠仅摘要，外部输入隐藏   暂停：灰显不可用   LogDock：自动跟随强制开启 |
| **panel**   专家会诊 | 主持人栏：模式选择、专家配置、议题上传、开始按钮   TopDeck：议题管理、专家配置   暂停/停止：隐藏 | 主持人栏：广播、暂停/停止、轮次控制   TopDeck：外部AI提问、实时备注   LogDock：按席位筛选 |
| **build**   工程交付 | 主持人栏：模式选择、开发配置、仓库挂载、开始按钮   TopDeck：工程配置、工具权限   暂停/停止：隐藏 | 主持人栏：广播、暂停/停止、构建触发   TopDeck：构建日志、外部评审   LogDock：错误高亮、构建输出 |
| **sequence**   顺序接龙 | 主持人栏：模式选择、顺序配置、主题设置、开始按钮   TopDeck：顺序编排、主题说明   暂停/停止：隐藏 | 主持人栏：广播、暂停/停止、下一位   TopDeck：当前发言人提示、接龙记录   LogDock：按顺序展示 |
| **debate**   辩论 | 主持人栏：模式选择、正反方配置、辩题设置、开始按钮   TopDeck：阵营配置、辩题说明   暂停/停止：隐藏 | 主持人栏：广播、暂停/停止、回合切换   TopDeck：当前回合、计分板   LogDock：按阵营筛选 |
| **cross**   质证 | 主持人栏：模式选择、控辩审配置、证据上传、开始按钮   TopDeck：角色配置、证据库   暂停/停止：隐藏 | 主持人栏：广播、暂停/停止、举证/质证   TopDeck：当前证据、质证记录   LogDock：证据时间线 |
| **group**   分组会诊 | 主持人栏：模式选择、分组配置、议题设置、开始按钮   TopDeck：分组管理、议题分配   暂停/停止：隐藏 | 主持人栏：广播、暂停/停止、组间切换   TopDeck：各组进度、汇总视图   LogDock：按分组筛选 |
| **open**   开放讨论 | 主持人栏：模式选择、自由配置、主题设置、开始按钮   TopDeck：参与者管理、主题说明   暂停/停止：隐藏 | 主持人栏：广播、暂停/停止、举手列表   TopDeck：发言队列、外部插话   LogDock：全量日志+搜索 |

### 模式增长维护策略（不失控）

1. **控件原子化**：所有控件拆分为独立原子组件（如`.btn-broadcast`、`.panel-topic`），通过CSS属性选择器控制显隐，不写零散JS判断。
2. **基础继承制**：定义`base`基础模式，所有新模式默认继承通用控件，仅需配置差异项，减少重复配置70%以上。
3. **配置驱动**：映射关系维护为JSON配置文件，而非硬编码；新增模式只需追加配置项，无需修改渲染逻辑。
4. **阶段通用规则抽离**：开会前统一隐藏暂停/停止、开会中统一显示（灰显/可用由模式决定），通用规则全局生效。

### 成本与反例

| 维度 | 成本说明 | 反例（禁止这么做） |
| --- | --- | --- |
| DOM | 所有控件常驻DOM，CSS控制显隐，无动态创建销毁，DOM总数固定 | 禁止每个模式单独写布局：8种模式就8套代码，维护成本指数级上升 |
| 状态 | 仅`data-mode`、`data-phase`两个状态键驱动全部显隐，零新增 | 禁止动态增删控件：事件绑定丢失、状态重置，400用例节点断言频繁失败 |
| 重排 | 模式切换仅触发CSS类变更，重排成本极低 | 禁止用JS控制显隐：性能差，状态与视图耦合，测试不稳定 |
| 测试 | 新增模式只需补充对应控件显隐断言，通用逻辑100%复用 | 禁止硬编码模式逻辑：每加一种模式就要改核心代码，扩展性为零 |
