## 三、分歧清单（需你拍板）

**D1 · phase 到底几态？**（家数比：三相 1 家 / 四态 2 家 / 五态 1 家 / 六态+正交 1 家 / 维持两相 4 家）
- 主张：Kimi 三相 `setup/running/done`；通义四态 `idle/configuring/running/paused`；DeepSeek 五态（+ready/ended）；ChatGPT 六态+attention 正交；豆包/Gemini/元宝/文心维持 pre/run（没跟上，视为弃权）。
- **我的判断**：**取 Kimi 三相 + 通义 paused + ChatGPT attention = `setup / running ⇄ paused / done`，attention 作为正交状态**。理由：done 是刚需（8 模式全有会后产物，现状摘要无处安放）；paused 独立才能表达"暂停了什么"（ChatGPT：⏸="已暂停派发"而非"全部停止"）；attention 正交解决"工具失败不该把会议改成暂停"这一真问题。ChatGPT 的六态里 READY/FINISHING 可以并入 setup/done 的子形态，不必单独建态。

**D2 · 工具面板放哪？**（全局右滑 dock 2 家 / 卡内抽屉 3 家 / ⧉弹出窗 2 家 / Seat Inspector 入 deck 1 家）
- **我的判断**：**全局右滑 tooldock，绑定 activeSeat（Kimi/通义方案）**。决定性理由是 Kimi 的：① 50 席 micro 密度（56px 高）卡内抽屉根本展不开；② 工具历史是纵向时间线，右侧空间匹配；③ 全局唯一一套 DOM，50 席共享 O(1) 换绑，卡内方案是 O(N) DOM。Gemini/文心的"卡内零重排"论点正确但不致命——tooldock 打开时用户本就不在看网格。卡内只留一行工具状态条（豆包/文心的 data-tool-state 方案，24px 定高）。

**D3 · 外部 AI 回答落位——通义正式推翻第 1 轮共识**（顶甲板 7/9 vs 右滑抽屉 1 家但理由最硬）
- 通义理由：表单要"持续打字别动我"，顶甲板契约是"随时收 0"——phase 变化/切域/窗口 resize 任一触发重排就失焦丢草稿；且工具台反正要做右滑抽屉，**一套抽屉两处用**更省。
- **我的判断**：理由成立，但与你原话"挪到上面"冲突。**给你两个选项**：
  - A（保守，尊重原话）：顶甲板折叠表单 + max-height 限高 + **编辑时锁定甲板不自动折叠**（借通义 `data-user-collapsed` 思路解焦点冲突）——成本低，先跑起来；
  - B（通义案）：右滑抽屉与工具台共用一套机制——交互最优，但偏离你原话。
- 我倾向 **A 先行、B 列为 v2 演进**（tooldock 落地后抽屉机制现成，迁移成本一天）。

**D4 · 工具权限默认值**（网页默认只读：通义/元宝/文心/豆包一致；API 默认：全开 1 家 / 标准 2 家 / 同白名单 1 家）
- **我的判断**：**网页=只读（文件读/检索），API=标准（+文件写/生成），shell/网络=全类型默认需确认**。元宝"API 默认全开"是明显反例（API 席位一样会执行工具），不采纳。

**D5 · API 席位要不要虚拟滚动？**（要 5 家 / 不要 2 家（Gemini"50 个 div 无压力"+原生滚动） / 离屏保留折中 1 家）
- **我的判断**：**先原生滚动+分组页签+密度档（Gemini 有理），不预建虚拟滚动**；100+ 席实测卡顿再上虚拟化，且届时用 DeepSeek 的离屏保留法（保 DOM 不断言）而非删除重建。虚拟滚动是复杂度大坑（滚动位置/键盘焦点/测试断言全受影响），50 帧的规模不值得。

## 五、经本地代码/事实核对后的修正

1. **通义"换席不丢东西"要打折**：换 src 后 `<webview>` 会重新加载页面——登录态靠 partition 保住，但**网页里的当次对话内容会丢**（除非该 AI 服务端有 history）。好在当前网页接入点固定 9 个，此设计暂缓（见上表），不构成近期风险。
2. **Gemini"50 div 无需虚拟滚动"与 Kimi"API 虚拟滚动"冲突**：两边都对一半。真实约束是：50 个**普通密度**卡片（240px 宽）没问题；但 50 个带 webview 的不行（不存在，webview 封顶 9）。取 D5 判断：先原生滚动。
3. **第 1 轮共识第 5 条（固定 DOM+hidden）确实要限定范围**——DeepSeek 的修正是对的：它适用于"控制面板 + 9 个 webview 格"，**不适用于未来 50+ API 格**（分页/搜索时要允许 DOM 增删，用离屏保留兜底测试）。
4. **豆包"网页席位工具默认全关" vs 通义/元宝/文心"默认只读"**：取"默认只读"（全关则工具对齐无意义，只读是安全与可用的平衡点）。
