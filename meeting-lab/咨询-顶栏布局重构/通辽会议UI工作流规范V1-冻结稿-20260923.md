## §2 R1'（Q3 终审规则·冻结）

**默认 A（顶甲板）+ 可见切换器 + 浮层硬性化 + 六组触发器 + 测量协议。**

- **F1 浮层硬约束**：追踪表/编辑体展开一律 absolute 浮层；z-index≥200；max-height = min(60vh, 目标行上方净空)，锚定摘要行下缘展开；点击外部收缩；浮层内滚轮/键盘/焦点独立闭环；关闭后网格几何零漂移。**任何展开形态不得挤压网格行高**（通义第三态条件）。
- **切换器**：`.header` 右侧常驻「甲板⇄抽屉」，≥1024px 显文字、小屏收图标但 1 击可达（元宝）；首次使用一次性引导（文心/豆包/Gemini）；切换器旁实时渲染「已用 k 次 / 自动回收率 m%」（Agnes 数据自破）；manualRatio>50% 连续 3 次会话 → 主动提示（DeepSeek）。
- **翻 B 触发器（OR，任一满足即机械翻，不辩论）**：
  - **T1 布局结构失败**（通义判据量化）：浮层遮挡致逐席操作无法达成，锚点/限高修复后仍消除不了；阈值：日均≥10 次∧单次≥5s（豆包）或 topRowObstructionRatio>20%（DeepSeek）。
  - **T2 持续时间税**（元宝+ChatGPT 修正）：分发半手动操作按 ≥20 会话稳定期均值 >30min/日（不用单日峰值）。
  - **T3 自动化成熟**（ChatGPT 变量错位修正）：**Precision=100%（硬门槛）∧ Recall≥80%**；手动率只作残差核验（≤(1−Recall)+5pp），**废除原"手动<20%"合取**（通义空集批判采纳）。Precision/Recall 的本职 = 自动化升级门槛。
  - **T4 行为投票**（DeepSeek+ChatGPT）：dockSwitchCount>10 且切 B 后停留>5min 占多数；或单轮 A⇄B churn>3 次无实质编辑（Gemini，视同 T1）。
  - **T5 零使用兜底**（Agnes）：N≥20 会话 externalPanelOpenCount=0 → 翻 B。
  - **T6 维护成本**（元宝）：F1 相关 bug 占全部 UI issue >30% 持续 2 周 → 翻 B。
- **翻回 A 触发器**（豆包）：连续 7 天手动占比≥50% ∧ 遮挡类操作<3 次/天 → 回 A（双向动态）。
- **中间态护栏**（DeepSeek）：三条件都不满足但 autoRecoveryCount>0 且 manualRatio∈[20%,50%] → 挂 attention 提示调优，不翻。
- **测量协议**：N≥20 且**按触发器独立计数**（元宝）；**逐 provider/席位保留记录，禁止均摊掩盖**（ChatGPT）；N=5 时做一次预检（DeepSeek）。

## §3 R2'（双半落位·冻结）

**一个逻辑组件、一份 DispatchJob/dispatchTrack 状态（8/8 零分歧），内部双页签「分发」「回收」，整体落位可切换（跟 R1 逃生舱走），单席深读/工具详情归 tooldock（Agnes 切割）。**

实现硬约束（缺一即是隐藏操作税）：
1. **页签 = 同一滚动容器的列过滤，不拆两个滚动容器**（Agnes）——切页签滚动位置同源不丢；
2. **视图状态逐页签保留**：筛选/搜索/滚动/选中席位（ChatGPT——否则 50+ 席"没丢数据但每次切页签都要重新找人"）；
3. **回收行内联该席的 dispatch 原文**（通义）——补采/交叉引用不切页签，读同份 state 的两个字段；
4. 宽 >1600px 提供**并排模式**（DeepSeek，覆盖"边写稿边看回收"高频对照）；
5. micro 密度下双页签内容超出时走 F1 浮层（元宝），不是复活 hybrid。

## §4 新增三条 L 级契约（开工前冻结，缺一不可）

- **C1 READY Gate = 不可变分发快照**（ChatGPT）：READY 时生成 snapshot{artifact/version + content hash + 时间戳}，DispatchJob 只执行快照；READY 后改稿 = 新快照。**杜绝"9 席回答的不是同一份问题"**。
- **C2 L1/L2/L3 逐席幂等**（ChatGPT）：DispatchJob 必须有 per-seat status + attempt + delivered 标记；重试只处理 failed 席位，**已 delivered 席位绝不重发**——降级链是"降级"不是"重跑"。
- **C3 DispatchJob 持久化**（元宝）：dispatchTrack 落盘（Electron store），应用崩溃/重启后可恢复续传，进行中状态不静默丢失。

## §5 两条真机闸门（开工即验，非辩题）

- **闸门甲（通义）**：--disable-gpu 真机断言——F1 浮层能稳定绘制在 9 个 `<webview>` 之上、浮层下网格保持**可见且可交互**（不允许 visibility:hidden 规避——那会杀死第三态本身）；不过 → T1 成立，自动翻 B。
- **闸门乙（通义）**：A⇄B 切换必须纯 CSS、零 reflow、webview 零销毁（每次切换断言 wv 存活）；不过 → 删切换器，只留单一布局。

## §6 P0 构建顺序（冻结）

1. **C1/C2/C3 三契约先行**：DispatchJob 骨架（快照+幂等+持久化）；
2. **分发半手动兜底**（用户当下最痛）：L1 CDP → L2 自动复制路径+模拟点击 → L3 逐席复制按钮，进度 k/N，失败席位显式点名；
3. **#2 三态追踪接引擎**（Agnes 前置论证：分发半追踪表依赖它）；
4. **自动回收抽取器并行真机验证**（5 家 DOM，per-provider selector 表 + 增量游标 + 稳定窗口；验证不过的 provider 自动降级手动，不阻塞 ship）；
5. R5 产物契约随回收半落地（索引+覆盖度红字点名+逐席原话）；
6. TopDeck/Grid/LogDock/ToolDock 四容器骨架 + F1 浮层 + 切换器 → **闸门甲/乙验收**。
