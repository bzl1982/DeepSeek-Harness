## Q1：L1/L2 路径大反转，全局降级还是按站点分主备？
结论：坚决支持 R7-1 的“全局降级”，反对“按站点分主备”。

* 攻击判定：F7-1 已经宣判了 L1（CDP 自动上传）在 GPT、千问、文心、谷歌、Kimi、DeepSeek 六席的彻底沦陷。如果强行搞“站点级主备”（如 Gemini/元宝/豆包走 L1，其余走 L2），会带来灾难性的 UI 灾难。用户在分发文件时，心智会被割裂为：“这三个站点我不用管它，那六个站点我得手动盯着复制”。
* 统一心智：必须建立统一的、以 L2/L3 手动为基座的全局心智。
* 站点级差异的真实落位：L1 只能作为纯粹的底层异步静默尝试。UI 表现上，9站点的进度条默认全部是“等待手动接入”或“一键复制路径/模拟点击”的 L2 状态。如果 Gemini 等站点的 L1 意外静默成功了，进度条直接卡嗒跳满变成“绿色成功”，减少用户一次操作；如果失败（如 GPT/谷歌），则毫无感知地停留在 L2 状态，等待用户点击。
* 战术划分：
* L2 起手（全局默认）：所有站点一网同仁，UI 核心提供“逐席一键复制路径 + 模拟点击触发文件框 + 进度 k/N 点名”。
   * L1 降为“彩蛋级异步静默”：仅在 Gemini、元宝、豆包后端做尽力而为（Best-effort）的静默 attach，成则惊喜，败则秒级释放控制权给 L2，绝不阻塞 UI。

------------------------------
## Q2：新增「闸门丙」的必要性，以及“甲板回退独立浮窗”是否推翻 Q3 默认 A？
结论：「闸门丙」极其必要，且回退独立浮窗不等于推翻顶甲板（Q3 默认 A）的价值。

* 闸门丙的防死锁价值：非常赞同。基于 F7-3（顶栏布局重构从未动工），如果 #dispatchdeck 贸然强行塞进顶甲板，而手动的“逐席复制/路径生成”等高频交互在真机 9 站点的 DOM 挤压下出现遮挡、点击失效或焦点丢失，会导致整个系统瞬间瘫痪。
* 回退浮窗 ≠ 空甲板：如果 dispatch 因为 L2 交互过载被迫退回独立浮窗（由 F1 浮层闸门甲接管），顶甲板（TopDeck）依然保留。
* 顶甲板的替代兜底内容：
* TopDeck 将转化为“9 席状态总控制台 + 全局信噪比脱敏监控（LogDock 的极简版）”。
   * 腾出来的空间放置：9站点的在线存活心跳、响应字数吞吐热力图、一键停止/重发全局指令。
   * Dispatch 的去向：化身为一个类似网盘上传悬浮窗的“高级分发飞翼”，按 F1 唤出，可任意拖拽或在边缘半隐藏，彻底解耦布局风险。

------------------------------
## Q3：5 大缺口的“归属层”判定（Provider 适配层 vs 布局耦合）
针对第 9 轮咨询案识别的 5 缺口，其技术归属判定如下，借此划清传输层与布局层的界限：

| 缺口编号与内容 | 归属层判定 | 顶甲板布局耦合风险与防范措施 |
|---|---|---|
| A. 成功判定不可靠 (残留旧文件导致误报) | 纯传输层 / 契约层 (Provider) | 无布局风险。通过在 DOM 侦察时加入时间戳及文件 Hash 校验解决，不影响 UI 表现。 |
| B. Kimi/DeepSeek 无专属通道 (直塞不稳) | 传输层基座 + UI 交互层 | 中风险。L2 化后，顶甲板需要为这两个站点暴露出极其醒目的“手动拖放热区”或“模拟点击强制提示”。如果挤在顶栏，可能导致热区太小，需确保 Grid 容器有足够的 Padding。 |
| C. 谷歌文件 attach 失效 | 纯传输层 (CDP/策略层) | 无布局风险。直接判死，在顶甲板 UI 上该站点的 L1 自动置灰，完全转为 L2 手动复制路径。 |
| D. 通义/文心/GPT 真实轮挂不上 | 纯传输层 (CDP) | 无布局风险。属于底层句柄或 DOM 变动问题。 |
| E. 跨轮残留文件污染 (重大隐患) | 传输层契约 + 布局联动 | 高风险。如果在 L2 基座下需要引导用户手动去点每个站点的“删除旧文件（X）”小按钮，顶栏太窄会发生误触。防范措施：在顶栏 dispatch 提供一个全局的“手动清理 9 席残留”强力按钮。 |

## Q4：L 级（必须再辩）遗留审视与优先级提堂
结论：无其他阻碍开工的 L 级隐患，布局可以立刻按返工闸门开工。但必须将一项透明广播条款紧急提 P0。

* 提 P0 项：透明广播 23 条兜底之 #19（发送前清空 + 回读校验）。
* 理由：在 L2 手动兜底升为基座后，用户在逐席贴路径或文件时，极易因操作过快产生残留污染（见缺口 E）。
   * 修正：必须把 #19 提速至 P0 构建。在顶栏 dispatch 模块中，设计一个明确的“清洁状态锁”：每当切换席位或准备新分发时，手动基座 UI 必须显式提示当前席位 input 是否为空，回读成功才亮起“请粘贴”绿灯。
