### 三、 针对 Q3 的答复：5 大缺口的“归属层”判定（纯传输层 vs 布局耦合风险）

结合第 9 轮咨询案沉淀的 5 缺口，其归属层判定如下：

* **缺口 A（成功判定不可靠 / `hasChip` 误报残留文件）**：
* **归属层**：**纯传输/适配层（Provider 适配层）**，与顶栏布局无关。
* **动作**：必须在进入顶甲板前，在底层注入“发送前清空 input + 发送后回读 DOM 唯一 token 校验”机制（即透明广播兜底条款 #19 的升级版）。


* **缺口 B（Kimi / DeepSeek 无专属通道）**：
* **归属层**：**纯传输层**。
* **动作**：实现统一的剪贴板降级代理（L3），将其包装为与 L1 统一的 Promise 接口。


* **缺口 C（谷歌文件 attach 失效）**：
* **归属层**：**纯传输层**。
* **动作**：针对谷歌 webview 单独重写 DataTransfer 构造与事件派发逻辑。


* **缺口 D（通义 / 文心 / ChatGPT 真实轮挂不上）**：
* **归属层**：**传输层 + 状态机层**。
* **动作**：由底层轮询状态机统一管控，向 UI 抛出明确的 `ERR_SESSION_HANG` 状态。


* **缺口 E（跨轮残留文件污染）**：
* **归属层**：**传输层生命周期管理**。
* **动作**：每次广播分发触发前，必须强制执行 `clearCrossTalk()` 内存与 DOM 清洗。



> **结论**：缺口 A~E 全部属于**底层传输与状态机治理**。它们在顶栏布局落进甲板前必须解决；如果把它们带进顶栏布局，不仅会增加布局耦合风险，还会让 UI 调试陷入“到底是 DOM 没摆好还是脚本没发出去”的泥潭。
