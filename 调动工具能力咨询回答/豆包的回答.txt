# 整体技术路线：网页Agent桥接 DeepSeek Harness + 本地工具 + 200+插件
核心目标：**网页端（浏览器）作为Agent入口，调用本地DeepSeek Harness客户端，复用Harness内置200+插件，同时扩展本地系统工具调用能力**。本质是做一层「网页Agent ↔ 本地Harness」双向通信网关，不能直接让浏览器沙盒访问本地资源，必须走本地服务中转。

## 架构分层（由外到内）
1. **网页前端层（浏览器）**
    - 载体：Web页面（Vue/React/原生HTML），也就是你之前的 `Agent Browser`
    - 职责：用户交互、对话界面、参数表单、任务编排预览、结果渲染
    - 限制：浏览器沙盒隔离，**无法直接访问本地文件、本地进程、Harness插件**，所有操作必须通过HTTP/WebSocket请求发给本地后端网关。
    - 能力：负责把用户自然语言任务，序列化成结构化任务JSON，下发给本地网关。

2. **本地网关服务（核心中转层，新增模块）**
    > 这一层是整个方案的关键，跑在本机，和DeepSeek Harness客户端同机。
    - 技术选型推荐：FastAPI（轻量、异步、方便做工具路由），端口监听在 `127.0.0.1`，**仅本地回环访问，不对外暴露**，保证安全。
    - 两大接口：
      - WebSocket：长连接，用于流式对话输出、实时任务日志、插件执行进度推送（适合LLM流式返回）
      - REST API：短连接，下发任务、查询插件列表、读取执行结果
    - 网关内部两个路由分支：
      ① **Harness插件路由**：网关作为Harness客户端的API调用方，对接DeepSeek Harness已有的插件调用接口，直接复用Harness内置200多个插件，不需要重新实现插件逻辑。
        - 流程：网页下发任务 → 网关转发请求给Harness → Harness执行插件 → 结果原路返回网页。
      ② **本地系统工具路由（扩展能力）**：网关自带本地工具执行器，负责浏览器网页无法做到的本地操作：读写本地文件、执行shell命令、启动本地程序、读取本机硬件信息等。
        - 安全限制：必须增加白名单机制，禁止高危命令；支持用户手动授权每一类本地操作。

3. **DeepSeek Harness客户端层（原有）**
    - 维持现有能力不变：模型推理、200+插件注册/调度、插件上下文管理、插件参数校验。
    - 改造最小化：开启Harness内置本地API服务（如果没有，给Harness加一个轻量内部HTTP接口，供网关调用），开放插件列表查询、插件调用、会话上下文读写接口。
    - 上下文策略：网关可以选择两种模式
      - 模式A：**Harness托管上下文**，网页只负责展示，所有对话历史、插件状态保存在Harness，适合重度插件任务。
      - 模式B：**网页托管上下文**，Harness只负责单次工具调用，适合网页侧自定义任务编排。

4. **本地资源层**
    文件系统、本地程序、终端、硬件，全部由网关服务访问，浏览器完全不碰。

## 两种部署方案对比
### 方案A：网关独立进程（推荐，低侵入）
- 结构：网页Agent（浏览器） ↔ FastAPI网关（独立进程） ↔ DeepSeek Harness Client
- 优点：
  1. Harness代码改动极小，几乎不侵入原有Harness插件系统，原有200+插件直接复用。
  2. 网关可以单独迭代，网页端、Harness客户端可以独立更新。
  3. 权限隔离清晰：网关统一管控本地工具权限，网页端无本地权限。
- 缺点：多一个后台进程，需要随系统开机自启管理。

### 方案B：网关嵌入DeepSeek Harness（一体化，高耦合）
- 在DeepSeek Harness内部嵌入FastAPI服务，网关作为Harness内部模块，不再单独启动程序。
- 优点：单程序启动，不需要额外管理独立网关进程。
- 缺点：改动Harness源码，后续升级Harness版本时合并成本高；网页、插件、本地工具逻辑耦合在一起。

> 建议优先走方案A，保持Harness本体干净，方便后续迭代你的Yue X、MediaForge等其他项目。

## 任务执行完整链路示例
用户在网页Agent输入：`帮我读取D盘文档目录，然后用Harness的代码格式化插件整理目录清单`
1. 网页前端：解析用户请求，生成结构化任务，通过WebSocket发送给本地网关。
2. 网关：解析任务，拆分两个工具调用：
   - 本地工具：读取D盘目录（网关本地执行）
   - Harness插件：调用Harness内置代码格式化插件
3. 网关先执行本地文件读取，拿到目录字符串；
4. 网关把目录字符串作为参数，调用DeepSeek Harness API，触发内置格式化插件；
5. Harness运行插件，返回格式化后的结果；
6. 网关汇总结果，流式推送回网页；
7. 网页渲染最终输出给用户。

## 安全设计要点（非常关键）
1. 网关只监听 `127.0.0.1`，拒绝外网IP访问，不会暴露端口到局域网/公网。
2. 本地工具调用做**命令白名单+路径白名单**，禁止rm、format等高危指令，文件访问限制在用户指定目录。
3. 每一类本地系统工具，增加确认弹窗：网页发起本地文件/命令调用时，Harness客户端弹出确认，用户手动允许才执行。
4. 通信鉴权：网关启动时生成一次性本地Token，网页连接必须携带Token，防止本机其他网页恶意调用网关。
5. 插件权限继承：复用Harness原有插件权限体系，网关不越权修改插件权限。

## 可选增强能力
1. 插件元数据同步：网关启动时自动拉取Harness全部200+插件清单（名称、描述、入参schema），同步到网页前端，网页可以生成插件选择面板、参数表单。
2. 任务编排：网页端可以做简易DAG，串联多个Harness插件+本地工具，实现多步骤工作流。
3. 会话同步：网页和Harness之间双向同步对话历史。
4. 日志持久化：网关统一记录网页发起的所有工具调用日志，方便调试。

## 技术风险与坑点预判
1. **跨域问题**：浏览器访问`127.0.0.1:xxxx`本地网关，会触发CORS。
    - 解决：网关配置CORS，仅允许本地网页origin；或者网页打包成PWA，规避部分浏览器限制。
2. **进程生命周期**：Harness客户端崩溃时网关需要捕获异常，向网页返回错误。
3. **插件上下文隔离**：多个网页会话同时调用Harness插件，要做好会话ID隔离，避免上下文串掉。
4. **大文件传输**：本地读取大文件传给Harness，不要一次性全量加载，用流式分片。

## 最简落地顺序（迭代优先级）
1. 给DeepSeek Harness暴露最小API：查询插件列表、执行插件调用、获取结果。
2. 搭建本地FastAPI网关，实现基础转发能力，打通网页 → 网关 → Harness调用链路。
3. 网关实现基础本地工具：文件读写，增加白名单与授权确认。
4. 网页Agent页面开发：对话界面、插件列表展示、流式输出。
5. 完善权限、日志、异常重试。
6. 扩展更多本地工具，支持工作流编排。
