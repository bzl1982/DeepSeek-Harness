既然已经接入了 DeepSeek Harness 客户端，要让网页版具备调动本地工具的能力，结合 Harness 的“一切皆插件”架构和 Cordis 内核，可以从以下几个技术路线入手：

本地工具插件化（核心路径）
Harness 的核心设计理念是“一切皆插件”，本地工具本质上就是运行在宿主进程里的可信代码。
开发范式：采用 ES 模块编写，推荐使用 apply 函数式。通过 ctx.tools.register(defineTool({...})) 注册工具，定义 name、description、parameters 以及实际执行代码的 execute 函数。
加载机制：利用 Cordis 内核的依赖注入（inject）和声明式依赖，框架会自动编排加载顺序。插件卸载时，通过 ctx.effect 注册的可逆副作用会自动按逆序清理，确保无内存泄漏。
本地接入：可以通过 dsh plugin --profile web add 命令安装第三方插件，或者在 Harness 源码仓库内新建本地插件目录，通过 cordis.yml 配置文件指定绝对路径进行插入加载。

利用 MCP 协议统一接入外部能力
如果本地工具较多，建议引入 Model Context Protocol (MCP) 来解耦 Agent 推理循环和外部工具生命周期。
架构分层：Harness 作为 MCP Host，通过内置的 MCP Client 与各个 MCP Server 通信。Server 内部调用本地文件、数据库或远程 API，对外只暴露标准的 JSON-RPC 接口。
传输方式：本地工具型 Server 适合用 stdio（标准输入输出）传输，由 Harness 直接拉起子进程；远程服务适合用 SSE/HTTP。注意 stdio 模式下 Server 日志需写入 stderr，避免污染协议数据流。

前端工具桥接（针对浏览器环境）
如果网页版需要直接访问客户端特定的资源（如读取本地传感器、访问客户端存储、执行 UI 操作），可以采用前端工具（Frontend Tools）方案。
执行机制：工具在客户端定义和注册，执行完全发生在客户端环境中，不在服务器上。服务器协调何时调用，客户端执行后将结果返回给服务器代理合并到响应中。
通信桥接：可以通过本地进程 IPC 桥接或 WebSocket 长连接，将网页前端的工具调用请求转发给本地运行的 Harness 服务端或本地代理网关执行。

权限管控与安全沙箱
调动本地工具涉及文件系统读写和 Shell 命令执行，必须做好权限隔离。
工作区隔离：Agent 仅能操作选定的本地目录（工作区）。涉及文件写入、删除或危险命令时，界面应弹出确认框需人工审批。
工具守卫：在工具执行流水线中加入 tools/pre-execute 拦截器，实现审批、拒绝或路径白名单校验，防止模型被注入恶意指令。

建议起步路线：
先跑通一个最小的本地工具插件闭环（apply(ctx) → 注册工具 → execute(args) → 返回结果），熟悉 Harness 的工具注册表和作用域分层机制后，再逐步引入 MCP 协议来批量接入复杂的本地服务。
