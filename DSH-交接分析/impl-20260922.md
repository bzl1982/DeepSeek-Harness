## 二、回滚方法（不行就改回来）

每个被改文件都留了**整文件级回滚备份**（未改动只保留原样）：

- `desktop/src/main.js.before-rewrite-20260922` ← 回滚 `main.js`
- `desktop/src/preload.js.before-rewrite-20260922` ← 回滚 `preload.js`

若某项改动导致 UI 异常，直接把对应 `.before-rewrite-20260922` 复制覆盖回原文件即可。
`desktop/src/inject/model-ui.js` 是新增文件，异常时删除它即可（main.js 读不到会安全降级为注入空字符串，不影响 DSH 原生）。

## 四、本轮关键发现（影响判断）

1. **V5–V11 真实实现已丢失**：`main.js.bak-current` 里 `MODEL_UI_JS` 是空壳；`main.js.bak-ui-20260921` 是更早版本（连 `MODEL_UI_JS` 都没有）。所以排序 / hover 子菜单是从零重写，而非还原。
2. **原 dumper 是死代码**：旧 `MODEL_UI_JS` 定义了却从未 `executeJavaScript`，所以 `%TEMP%/dsh-model-ui-dump.json` 从未生成；本轮已补上执行调用，并保留 `?dshDump=1` 调试入口。
3. **「打开并登录」按钮此前不存在**：全仓搜不到该字符串，它是报告期望我们注入的；本轮已在设置页网页智能体分组内注入并接通 `openLogin` 桥 + 主进程同分区窗口。

## 五、仍存在的硬约束（实现时严格遵守）

- 排序 / 移动类 DOM 操作**只在设置页**执行；主页模型弹窗**绝不移动/删除**任何 dsh 原生节点（只做只读 hover 增强）。
- 禁止任何 `max-height` / `overflow:hidden` 隐藏样式（产品禁滚动）。
- hover 飞出只用 CSS `position` + 自建 flyout 节点，不重排 dsh 原生树。
- 网页 webview 登录严格走 `persist:agent-{providerId}`，不混用公用 partition。
