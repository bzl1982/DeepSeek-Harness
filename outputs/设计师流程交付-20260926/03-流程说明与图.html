流程推理修订版 · 2026-09-26 · 严格人工闸门

多 AI 软件开发协作台

用户用免费的网页 AI 负责创意、分析和代码草稿；API 接入的智能体负责收集、整理、操控电脑、连接插件、写入工作区、集成、构建和测试。两种方式可以互换，但所有重要动作都必须经过同一套用户确认规则。

唯一推进规则：当前步骤产出结果和证据后，系统只能等待用户点击 合格 或 返工。
点击“合格”才解锁下一步骤 点击“返工”才生成返工回路 不点击就停留在当前步骤 系统不能替用户做决定

先修正的逻辑问题

这些不是视觉细节，而是会导致系统“看起来完成了，实际上没有经过用户确认”的状态错误。

1. 删除自动推进主流程

原稿里的“限范围自动推进”与当前要求冲突。自动保存、索引、计算校验和收集已到达的回复可以作为步骤内部动作，但不能自动发送、改文件、运行电脑、构建或进入下一步。

暂停不再是第三个按钮：用户不点击即可保持等待；发生异常时，用户用“返工”发起重试、补件、换 AI 或回到责任步骤。

2. “合格”不等于篡改技术事实

“合格”表示用户接受当前步骤的产物，允许进入下一步；它不能把测试失败、文件缺失、未执行或发送不确定改写成“技术通过”。

证据不足时，“合格”应不可用；用户只能点击“返工”，直到产物和证据达到本步骤标准。

3. 发送和接收必须分开记账

附件挂在网页输入框里不代表发送成功，AI 回复结束也不代表文件已经进入工作区。每个收件人都要有发送状态、消息 ID、附件清单、文件路径或下载结果。

群发部分成功时，只对失败收件人返工，不能把整批假报成功，也不能无凭据重复发送。

4. API 智能体不能兼任裁判

API 智能体可以操控 PC、调用插件、收集网页 AI 的文本和文件、组织代码、构建和测试，但不能自动点击“合格”、擅自扩大权限、把自己的判断当作用户决定。

网页 AI 的答案是候选材料；API 智能体的执行结果是证据；最终是否进入下一步仍只看用户按钮。

四个角色的边界

角色可以由多个服务实例承担，但权限边界不能混在一起。

用户：唯一决策者写目标、选收件人、选择群发或定向发送、核对材料和证据，并在每一步点击“合格”或“返工”。
网页 AI：创意与代码来源负责头脑风暴、方案比较、代码草稿、补丁和说明。它的输出必须标注来源与版本，不能直接代表项目已通过。
API 智能体：执行与组织在当前授权范围内操作 PC、浏览器、插件、文件、命令、构建和测试；发现计划变化或权限超范围就停下等待用户。
工作区：事实与证据账本保存消息、附件、文件、差异、日志、测试、权限和用户决定；每条结果都能追溯到步骤、版本和来源。

统一状态机

把“AI 说做完了”和“用户确认可以往下走”明确分开。

准备本步骤冻结输入、目标、负责人和权限
→
执行并收集证据产出文本、文件、差异、日志或回执
→
等待用户决定只有按钮结果能改变流程状态
合格冻结当前版本，记录用户决定，只解锁定义好的下一步骤；不会替未来步骤预先授权。
返工记录原因、目标步骤和新要求，保留旧版本，回到责任 AI 或 API 智能体；受影响的下游版本标记为“待复核”。
内部动作的边界：自动保存、生成校验和、建立索引、整理已收到的回复、渲染差异等可以在当前步骤内自动完成；但它们不能自行产生下一步骤、对外发送、改写工作区、执行高风险命令或提交远端。

两种常用写程序方式

两条路线在交接后汇合到同一套 API 执行、验证和用户验收流程。

方式 A：网页 AI 直接写代码

用户把需求和资料发给一个或多个网页 AI，网页 AI 负责创意、实现草稿、文件和补丁。用户先在网页 AI 侧反复“返工”，得到可交接的一版，再由 API 智能体收集并落入本地工作区。

路线：网页 AI 创意／写码 → 用户合格 → API 智能体收集文件 → 用户合格 → 整理集成 → 用户合格 → 审查、构建与测试

方式 B：网页 AI 出主意，API 智能体落地

网页 AI 提供思路、规则、代码片段、审查意见或修改方案；API 智能体在用户授权范围内操作电脑和插件，真正创建、修改、集成和运行项目文件。

路线：网页 AI 建议 → 用户合格 → API 智能体执行 → 用户合格 → 审查、构建与测试

主流程图：每一步都有同一个用户闸门

下面的“合格／返工”是业务决策，不是 AI 自报状态。所有步骤都要绑定当前版本和证据。

01

建立项目边界与工作区

用户 + API 智能体
本步骤做什么明确目标平台、项目目录、已有代码、禁止修改范围、插件和 PC 操作权限。
合格证据项目卡、工作区路径、资源清单、权限范围、交付目标。
下一步进入需求与验收条件整理。
用户闸门合格返工返工时只修正边界或权限，不得悄悄带入后续假设。
02

整理需求、流程和验收标准

网页 AI 负责整理，用户负责决定
本步骤做什么明确用户、输入、输出、正常流程、异常流程、不做什么，以及怎样判断成功。
合格证据需求版本、验收清单、未决问题和已知限制。
下一步进入消息和材料包准备。
用户闸门合格返工需求变化会使受影响的后续版本变为“待复核”，不会覆盖旧版。
03

组装消息与材料包

用户选择发送范围
本步骤做什么编辑文本，选择需求、代码、文档、图片、图标、压缩包等资料，并选择全部 AI、网页 AI 群组、API 智能体或指定 AI。
合格证据不可变消息包 ID、收件人清单、附件清单、文件版本或校验信息、上下文说明；实际消息 ID 在发送后产生。
下一步仅允许向已确认的收件人发送。
用户闸门合格返工合格只授权这一个消息包和这批收件人，不授权未来的自动群发。
04

发送到网页 AI，并收集实际回执

系统发送，用户验收发送结果
本步骤做什么按收件人执行群发或定向发送，收集各 AI 的回复文字、网页生成的文件、下载结果和失败信息。
合格证据每个 AI 的发送状态、消息 ID、回复状态、附件是否可读、文件是否真实落地。
下一步进入网页 AI 创意／代码回合。
部分成功、收件人未收到、附件缺失或状态不确定：点击“返工”，只处理受影响的收件人或材料；禁止盲目重发。
用户闸门合格返工网页附件挂载不等于发送成功，AI 回复结束不等于文件已收集。
05

网页 AI 创意、方案和代码回合

一个或多个网页 AI
本步骤做什么让网页 AI 提供创意、技术建议、代码草稿、补丁、说明或审查意见；可以继续群发，也可以只追问指定 AI。
合格证据按 AI 分开的回答、文件、来源、基于哪个需求版本、未回答项和分歧点。
下一步筛选并冻结准备交给 API 智能体的材料。
答案互相矛盾时不能投票代替事实核验；点击“返工”重新提问、换 AI、补上下文或要求最小可验证示例。
用户闸门合格返工网页 AI 只提供候选材料，不能把候选材料直接当作项目文件已通过。
06

冻结网页 AI → API 智能体的交接包

用户选材 + API 智能体核验
本步骤做什么选择要采用的回答和文件，去重，标记取舍，只从用户选定的会话和目录把网页文件下载或复制到受控工作区。
合格证据交接包清单、来源 AI、原始消息、文件路径、版本／校验值、采用理由和未采用项；不得默认扫描全部浏览器历史或全部磁盘。
下一步API 智能体读取交接包并形成执行计划。
API 智能体无法访问网页会话或文件时，状态必须是“待用户补件”，不能凭文件名、旧文件或 AI 口述冒充已收集。
用户闸门合格返工合格只冻结这批交接材料；后续重新选材必须生成新版本。
07

API 智能体拆分任务、制定计划与权限范围

API 智能体拟定，用户授权
本步骤做什么按依赖拆成任务批次，说明负责人、输入、输出、读写目录、插件、窗口、命令、回退方式和验收点。
合格证据任务索引、依赖关系、文件锁定范围、分步计划、权限白名单、风险提示和预计产物。
下一步只为前置条件已满足的任务建立独立闭环；无关任务继续等待。
计划临时需要扩大目录、权限、网络或删除／覆盖文件时，原授权失效，必须返工形成新计划。
用户闸门合格返工API 智能体可以执行计划，但不能自行把执行结果判为合格。
08

按任务批次组织、写入和集成代码

API 智能体 + PC／插件
本步骤做什么逐个任务执行：按方式 A 收集网页 AI 写出的文件，或按方式 B 根据网页 AI 建议真正创建／修改项目文件，再按依赖集成。
合格证据实际文件路径、变更差异、版本快照、运行命令、日志、未完成项和冲突处理记录。
下一步进入静态检查、单元测试或项目测试。
写入失败、改错目录、版本过期、文件冲突或超出授权范围：点击“返工”回到本步骤，不得继续测试旧结果。
用户闸门合格返工代码“写进去了”不等于代码正确；这里验收的是实际变更和证据是否齐全。
09

独立 AI 审查与问题处理

网页 AI 审查，API 智能体整理，用户决定
本步骤做什么把每个任务的同一版实际代码和证据交给未编写、未修正该任务的网页 AI 独立审查，按问题严重性归类并核对分歧。
合格证据审查 AI、审查版本、问题清单、复现依据、已修问题、驳回理由和未解决风险。
下一步无阻塞问题则进入验证；有问题则返工代码或重新审查。
审查 AI 不足、意见冲突或问题无法复现：点击“返工”补上下文、换审查 AI或要求验证，不得把缺少审查当成审查通过。
用户闸门合格返工用户可以接受已知风险继续，但不能把未执行的审查或未解决的问题改写成无风险。
10

验证、构建和运行检查

API 智能体执行，用户逐结果验收
本步骤做什么按验收清单运行检查、测试、构建、打包、安装或启动验证；每一项标记通过、失败或未执行。
合格证据与当前代码版本对应的测试日志、构建日志、安装包路径、启动结果和已知限制。
下一步进入用户实际验收和本地交付。
失败或未执行的检查不能被“合格”改写；点击“返工”把真实日志交给网页 AI 或 API 智能体处理，再用新版本重验。
用户闸门合格返工只有本轮产物、代码版本和验证证据能互相对应时才可合格。
11

用户验收与本地交付

用户实际操作
本步骤做什么用户安装、启动、操作核心流程，检查是否满足需求和验收条件。
合格证据验收记录、交付目录、版本号、运行方式、已知限制和未解决问题。
下一步进入可选的仓库同步；未点击则停在本地交付。
不通过：点击“返工”回到相关代码／验证步骤；新增需求不要伪装成缺陷，建立新的需求版本。
用户闸门合格返工“合格”只完成本地交付，不自动上传、合并、公开发布或部署。
12

核对并同步仓库

API 智能体执行，用户决定远端变更
本步骤做什么检查仓库、分支、待提交文件，排除密钥、登录态、私人资料和无关修改，再执行提交或推送。
合格证据提交 ID、目标分支、远端回执、未同步文件和同步失败信息。
下一步完成本轮；合并主分支、发布和部署另开明确步骤。
同步失败只返工同步环节；本地交付仍保留，不要因为远端问题重做开发。
用户闸门合格返工没有用户点击，API 智能体不得提交、推送或改变远端状态。

任务级闭环：项目步骤通过后仍要逐任务确认

任务可以并行准备，但每个任务都必须有自己的版本、证据和用户决定；一个任务返工不会自动打回无关任务。

T1 冻结任务包

确认任务目标、前置依赖、负责人、输入材料、可读写文件、接口、产出、验收条件和回退方式。

合格 只解锁这个任务的准备动作；返工 回到任务拆分或补齐材料。

T2 确认收件人并执行

用户选择发给哪个网页 AI、API 智能体或指定 AI 群组，确认本任务消息和附件后才执行发送、文件收集或 PC 操作。

合格 只授权本任务这一次动作；返工 修正收件人、上下文、权限或附件。

T3 核对实际产物

检查真实文件、差异、日志、运行结果和未完成项；“AI 回复了”不能替代“文件已落地且内容正确对应版本”。

合格 才能进入独立审查；返工 回执行或文件交接。

T4 独立审查与问题处理

通常选择 2–3 个未编写、未修正该任务的网页 AI 审查同一版本。意见冲突先核实，不能用多数票代替事实。

合格 允许任务进入任务验收；返工 修正后必须用新版本重新核验。

T5 任务最终闸门

用户确认当前任务的代码、证据、审查结果和已知风险。通过后，才解锁依赖它的下游任务；未通过只影响相关任务和依赖结论。

合格 解锁下游；返工 指定责任步骤、责任 AI 和返工目标。

并行规则

没有依赖关系的任务可以分别准备，但不能共用未确认的文件写入范围；集成前必须确认所有必要任务已通过且版本没有过期。

依赖任务的通过状态、文件锁和接口结论发生变化时，下游自动标为“待复核”，不能继续沿用旧确认。

群发、定向发送和文件交接

消息系统是协作工具，不是绕过用户闸门的自动通道。

动作用户如何决定系统必须记录不能假设的事情
群发同一份材料发给选中的全部网页 AI用户确认收件人集合和消息包后，点击当前步骤的“合格”；只向这批收件人发送。批次 ID、每个 AI 的消息 ID、发送状态、回复状态、失败原因。群发不代表所有 AI 都收到，也不代表所有回答都有效。
定向发送只发给指定 AI，附加专属上下文用户逐项确认收件人、专属提示和附件；返回结果仍按 AI 分开验收。收件人、上下文版本、附件版本、实际回执和文件入口。一个 AI 的回答不能自动代替另一个 AI 的回答。
转发／二次提问把某个结果发给全部或指定 AI必须生成新的消息包和新的版本；用户再次选择收件范围并点击“合格”。原消息 ID、新消息 ID、引用范围、是否包含附件原件。转发不能悄悄改变原始材料，也不能把旧回复当成新回复。
文件交接文本、资料、代码、图片、图标或压缩包用户确认要采用的文件和来源；API 智能体只能读取确认过的交接包。原始来源、文件路径、大小、校验值、版本、下载／复制时间。文件名存在不代表内容可读，网页里显示不代表本地已落地。

返工规则和异常状态

返工不是删除历史；它是带原因的新版本回路。

一次返工必须留下五件事

  • 返工发生在哪个步骤、哪个版本。
  • 用户指出的具体问题和期望结果。
  • 返工责任人：指定网页 AI、网页 AI 群组或 API 智能体。
  • 需要重新提供的材料、权限和验收条件。
  • 哪些下游结果继续有效，哪些只标记为待复核。

以下情况不得显示“可进入下一步”

  • AI 超时、部分回复、收件状态不确定。
  • 附件缺失、文件打不开、文件来源或版本不明。
  • API 智能体没有实际写入文件或日志无法对应当前版本。
  • 测试失败、构建失败、安装包不存在或未执行关键验证。
  • 计划需要扩大权限、目录、网络或操作范围。

设计和实现时的最低可见信息

  • 当前步骤、项目／任务版本、正在等待谁。
  • 当前步骤的输入、输出、证据和未完成项。
  • “合格”会解锁哪一步，“返工”会回到哪里。
  • 本次消息发给了谁，哪些已收到，哪些失败或待核实。
  • 每个文件的来源、真实路径、版本和校验信息。
  • API 智能体当前可读写的目录、插件和命令范围。
  • 网页 AI 写出的候选材料与 API 智能体落地文件的区别。
  • 代码验证、用户验收、本地交付、仓库同步的区别。
这份页面描述的是严格人工确认的目标流程：免费网页 AI 可以承担创意和代码生产，API 智能体可以承担 PC 操作和最终组织构建，但任何业务步骤都不能绕过用户的“合格／返工”决定。页面内的“自动”仅指当前步骤内部的机械整理，不代表自动推进。
