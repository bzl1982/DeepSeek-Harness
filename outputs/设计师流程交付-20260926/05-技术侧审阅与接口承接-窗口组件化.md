## 二、两个必须让设计侧知悉的技术事实

### 1. 内容区是「活网页」，不是静态截图——裁切语义在实现里不成立

设计稿里 webview 区用 `scaleMode: FILL` 裁切显示截图，这个取舍（"内容占比小的网站显示效果好"）在真实实现里**不完全成立**：

- 实现时内容区是可交互的 webview，网页会按容器实际宽高**自适应重排**（响应式布局），不会像图片那样裁掉边缘。
- 视觉上"窗口=网页缩小版"成立，但每家网站在同一个窗口尺寸下会呈现各自的重排结果，而不是同一张截图的固定裁切。
- 设计稿里的截图仅作为**视觉示意和加载前占位**；壁纸底色的真实作用是「webview 加载中/加载失败的空态背景」，不会盖住网页内容。
- 结论：设计不用改，但预期要对齐——实现后各窗口长什么样由各家网站响应式决定，设计稿无法像素级锁定网页席位的内容；API 席位（无网页）才是设计稿可以完全锁定的部分。

### 2. 生成型模型是异步任务，必须有「生成中」态

图像/视频生成不是流式聊天，链路是：提交提示词 → 任务排队 → 轮询进度 → 返回结果（可能数秒到数分钟）。因此：

- 对话型三态（常态/拖拽悬停/已附件）之外，生成型**必然需要第四态：「生成中」加载态**（进度指示+可取消）。这不是可选项，是任务机制决定的。
- 技术侧会为生成席位新增独立契约（提交任务/轮询/取结果/取消），与聊天通道的 SSE 流是两套协议。
- 建议：本轮设计稿先用文字占位没问题，但**"生成中"态的视觉占位建议先留一个占位框**，避免将来加态时窗口壳骨架要返工。

## 三、接口约定（可直接并入接口文档）

### 1. 席位显示规则

```
大字区（品牌简称）= provider.brandShort，缺省回退 provider.name 去掉"中转/分组"等后缀
小字区（完整型号）= seat.model（完整 model id，超长截断+悬停显全）
字体选择 = 名称含中文 → 该风格档的中文字体对；纯西文 → 西文字体对（自动，不给用户选）
```

### 2. providers.json 新增可选字段（向后兼容，旧数据不受影响）

```json
{
  "brand": "deepseek-blue",        // 色板档位 key，8 档之一或同色系深浅扩展档
  "brandShort": "DeepSeek",        // 大字区品牌简称
  "brandLogo": "assets/logos/deepseek.png"  // 可选；为空回退文字标识
}
```

> 字段命名以此处为准（00 设计文档 §6 已同步对照）。00 文档中的 `semanticColor`/`displayName`/`logoAsset` 分别对应本表 `brand`/`brandShort`/`brandLogo`；`genType`（text2img/text2video，仅生成型）与 `webUrl`（仅真实网页版席位）也落在 provider/seat 注册数据上，生成型必填 `genType`。

### 3. 席位类型

```
seat.kind = "chat" | "generative"     // 生成席位走画廊+提示词骨架
kind=generative 时必显「生成中」加载态
```

### 4. LOGO 显示规则（承接设计侧待办第 4 条）

```
尺寸：固定 64×64 逻辑像素，等比缩放，容器内水平垂直居中
资源：PNG 优先（512×512 源图，透明背景）；SVG 需预转换为 PNG（复用设计侧 sharp 流程，density:300）
回退：brandLogo 缺失/加载失败 → 显示 brandShort 文字标识（虚构角色如 Agnes 永远用文字标识）
```

### 5. 色板档位（8 档语义色 + 扩展规则）

```
8 基础档：deepseek-blue / kimi-teal / doubao-orange / qwen-purple / wenxin-red / gemini-bluepurple / gpt-green / neutral-grayblue
扩展：同色系深浅档，每色系最多 3 家；满员后新增厂商必须走色系评审
校验：新增模型表单读取 providers.json 统计各档占用，已满档位禁用（运行时校验，不只文档约定）
```
