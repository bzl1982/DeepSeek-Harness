可以，而且你这个难题其实有一个很明确的落地解法：**不要让网页版 AI 获得“操作电脑”的权限，而是让通辽会议直接读取它已经生成到网页 DOM 里的回复。**

你现有的 Electron + 9 个 WebView + CDP 架构正好适合做这个，不需要重新搞 Playwright 浏览器群，也不需要让 AI 自己执行本机命令。

Electron 本身支持对页面执行 JavaScript，WebView preload 也可以通过 IPC 把页面事件传回宿主程序。([Electron][1])

# 我建议你把它做成「WebAI Reply Bridge」

整体链路：

```text
              ┌──────────────────────┐
              │     通辽会议 Core     │
              │   Meeting Core       │
              └──────────┬───────────┘
                         │
                  request / round
                         │
        ┌────────────────┼────────────────┐
        │                │                │
   ┌────▼────┐      ┌────▼────┐      ┌────▼────┐
   │ WebAI 1 │      │ WebAI 2 │ ...  │ WebAI 9 │
   │ ChatGPT │      │ DeepSeek│      │  千问等  │
   └────┬────┘      └────┬────┘      └────┬────┘
        │                │                │
        │ DOM变化监听     │ DOM变化监听     │ DOM变化监听
        ▼                ▼                ▼
   Reply Bridge      Reply Bridge      Reply Bridge
        │                │                │
        └────────────────┼────────────────┘
                         │
                     IPC / CDP
                         │
                         ▼
               ┌──────────────────┐
               │ Meeting Core     │
               │ 收到 AI 回复      │
               └────────┬─────────┘
                        │
               ┌────────▼────────┐
               │ Message Store   │
               │ 保存/广播/注入    │
               └─────────────────┘
```

核心思想就是：

> **用户不用点“复制”。**
>
> AI 回复一边在网页里流式生成，Bridge 一边观察。
>
> 回复完成后，Bridge 自动把完整文本交给通辽会议。

# 一、千万不要把“自动点击复制”作为主方案

你现在看到：

```text
AI回答
        [复制]
```

最容易想到：

```text
找到复制按钮
↓
自动点击
↓
读取剪贴板
↓
交给通辽会议
```

这个可以做，但我建议只当 **Fallback**。

原因很简单：

1. 不同网站按钮 DOM 不一样。
2. 有的“复制”实际上复制的是代码块。
3. 有的网站要求真实用户手势，脚本 click 不一定能触发 Clipboard API。
4. 用户自己的剪贴板可能被污染。
5. 页面更新后按钮 DOM 很容易变化。
6. 流式生成过程中，复制按钮可能还没出现或复制的是不完整答案。

所以应该反过来：

```text
DOM 是主通道
↓
MutationObserver 监听
↓
拿到正在生成的答案
↓
判断生成结束
↓
提交完整答案
```

而“自动点击复制”只做：

```text
DOM 提取失败
        ↓
找到最后一个回答的复制按钮
        ↓
尝试自动复制
        ↓
读取剪贴板
        ↓
恢复用户原来的剪贴板
```

这样可靠性高很多。

# 二、真正关键的是「Reply Observer」

你可以给每一个 WebAI 页面注入一段很小的 JS。

例如：

```js
(() => {
  if (window.__TM_REPLY_BRIDGE__) return;

  window.__TM_REPLY_BRIDGE__ = {
    version: 1,
    installedAt: Date.now()
  };

  let lastText = "";
  let lastChangeAt = Date.now();
  let finalSent = false;
  let timer = null;

  function visible(el) {
    if (!el) return false;

    const style = getComputedStyle(el);

    return (
      style.display !== "none" &&
      style.visibility !== "hidden" &&
      el.offsetWidth > 0 &&
      el.offsetHeight > 0
    );
  }

  function cleanText(text) {
    return (text || "")
      .replace(/\u00a0/g, " ")
      .replace(/\r\n/g, "\n")
      .replace(/\n{3,}/g, "\n\n")
      .trim();
  }

  function getLabel(el) {
    return [
      el.getAttribute("aria-label"),
      el.getAttribute("title"),
      el.innerText,
      el.textContent
    ]
      .filter(Boolean)
      .join(" ")
      .trim();
  }

  function findCopyButtons() {
    const nodes = [
      ...document.querySelectorAll(
        "button,[role='button'],[aria-label],[title]"
      )
    ];

    return nodes.filter(el => {
      if (!visible(el)) return false;

      const label = getLabel(el).toLowerCase();

      const isCopy =
        label.includes("copy") ||
        label.includes("复制");

      const isCodeCopy =
        label.includes("copy code") ||
        label.includes("复制代码");

      return isCopy && !isCodeCopy;
    });
  }

  function extractCandidate() {
    const buttons = findCopyButtons();

    if (!buttons.length) return null;

    const button = buttons[buttons.length - 1];

    let node = button;
    let best = null;

    for (let i = 0; i < 8 && node; i++) {
      const text = cleanText(node.innerText);

      if (
        text.length >= 2 &&
        text.length <= 500000
      ) {
        best = node;
      }

      node = node.parentElement;
    }

    return best ? cleanText(best.innerText) : null;
  }

  function isGenerating() {
    const nodes = [
      ...document.querySelectorAll(
        "button,[role='button']"
      )
    ];

    return nodes.some(el => {
      if (!visible(el)) return false;

      const label = getLabel(el).toLowerCase();

      return (
        label.includes("stop generating") ||
        label.includes("停止生成") ||
        label.includes("停止回答") ||
        label.includes("cancel generation") ||
        label.includes("取消生成")
      );
    });
  }

  function emit(type, text) {
    window.postMessage({
      source: "TM_REPLY_BRIDGE",
      type,
      text,
      timestamp: Date.now()
    }, "*");
  }

  function scan() {
    const text = extractCandidate();

    if (!text) return;

    if (text !== lastText) {
      lastText = text;
      lastChangeAt = Date.now();
      finalSent = false;

      emit("reply-progress", text);
    }

    const stableMs = Date.now() - lastChangeAt;

    if (
      !isGenerating() &&
      stableMs >= 1200 &&
      text.length > 0 &&
      !finalSent
    ) {
      finalSent = true;

      emit("reply-complete", text);
    }
  }

  const observer = new MutationObserver(() => {
    clearTimeout(timer);

    timer = setTimeout(scan, 150);
  });

  observer.observe(document.documentElement, {
    subtree: true,
    childList: true,
    characterData: true
  });

  window.addEventListener("load", scan);

  scan();
})();
```

这个只是**第一版通用原型**。

真正的产品版，不应该把所有网站硬塞进这一段代码，而应该做成：

```text
ReplyBridge
│
├── Observer
│
├── CompletionDetector
│
├── TextNormalizer
│
├── TurnTracker
│
├── Transport
│
└── SiteAdapter
      ├── ChatGPTAdapter
      ├── DeepSeekAdapter
      ├── QwenAdapter
      ├── KimiAdapter
      ├── DoubaoAdapter
      ├── ClaudeAdapter
      ├── GeminiAdapter
      └── ...
```

这样才适合你的“通辽会议”。

# 三、最重要的一点：不要依赖固定 3 秒

这其实正好可以解决你之前通辽会议的另一个 BUG。

你原来大概是：

```text
上传
↓
sleep(3000)
↓
点击发送
↓
等待
↓
不知道什么时候完成
```

应该改成：

```text
发送请求
↓
Reply Observer 检测到新 Assistant Turn
↓
持续获取文本
↓
streaming
↓
检测生成状态
↓
DOM 稳定
↓
生成结束
↓
reply-complete
```

也就是说：

```text
RUNNING
   │
   ▼
AI开始回答
   │
   ├──────→ reply-progress
   │
   │
   ▼
文本继续变化
   │
   ├──────→ reply-progress
   │
   ▼
停止生成按钮消失
   │
   ▼
DOM 继续观察
   │
   ▼
文本连续 1200ms 没变化
   │
   ▼
reply-complete
```

这比：

```js
setTimeout(..., 3000)
```

靠谱得多。

Electron 的页面脚本执行和 CDP 的 `Runtime.evaluate` 都可以做这类页面内 JS 控制。([Electron][1])

# 七、Electron 里怎么把网页结果送回通辽会议？

你现有工程可以直接走 Preload → IPC。

Electron 官方本身就支持 preload 与 IPC，并且 `<webview>` 可以通过 guest preload 与宿主通信。([Electron][2])

例如：

```js
// webai-preload.js

const { ipcRenderer } = require("electron");

function sendToMeeting(payload) {
  ipcRenderer.send("tm:webai-reply", payload);
}
```

然后：

```js
window.addEventListener("message", event => {
  if (
    event.data?.source !== "TM_REPLY_BRIDGE"
  ) {
    return;
  }

  sendToMeeting({
    type: event.data.type,
    text: event.data.text,
    timestamp: event.data.timestamp
  });
});
```

Main：

```js
ipcMain.on(
  "tm:webai-reply",
  (event, payload) => {

    const webContentsId =
      event.sender.id;

    const seat =
      seatRegistry.getByWebContentsId(
        webContentsId
      );

    if (!seat) return;

    meetingCore.handleWebAIReply({
      seatId: seat.id,
      provider: seat.provider,
      ...payload
    });
  }
);
```

这样：

```text
ChatGPT WebView
      │
      ▼
webai-preload.js
      │
      ▼
IPC
      │
      ▼
Electron Main
      │
      ▼
Meeting Core
```

完全不需要让 ChatGPT “操作电脑”。

# 十、真正的“完成条件”我建议做四层


# 十四、最后我建议你把它正式命名

这个模块我建议就叫：

**`WebAI Bridge`**

内部拆成：

```text
core/
  webai/
    WebAIAdapter.js
    WebAIReplyBridge.js
    WebAICompletionDetector.js
    WebAITurnTracker.js
    WebAIMessageStore.js

    adapters/
      chatgpt.js
      deepseek.js
      qwen.js
      kimi.js
      doubao.js
      wenxin.js
      gemini.js
```

```js

seat.on("reply-timeout", handler);
```

这样一来，**网页版 AI 在通辽会议里就不再是“一个只能显示的网页”，而变成一个真正有 Input / Output 生命周期的 WebAI Seat。**

**我认为你当前最值得优先攻克的，其实就是这个 `WebAIReplyBridge`，因为一旦“自动收回复”打通，你前面一直卡住的“9 个 AI 为什么不能真正自动开会”的核心瓶颈就解决了一大半。**
